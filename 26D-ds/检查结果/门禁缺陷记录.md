# 门禁缺陷记录

本文件记录本次运行中发现并处理的门禁与环境缺陷，供复核与回溯。

## 缺陷一：技术路线图质量检查未支持 HTML 锁定模式

### 现象

`check_roadmap_quality_notes.py` 对每个被识别为技术路线图的 manifest 条目执行判定：

```
if str(item.get("generator", "")).lower() not in {"drawio", "imagegen", "image gen", "openai-imagegen"}:
    errors.append("技术路线图 generator 必须与 Draw.io/AI 锁定模式一致。")
```

而本次运行的锁定绘图模式为卡片指定的 `HTML矢量成图`，其 manifest 条目的 `generator` 必须为 `html`。
因此该判定在 HTML 模式下必然失败；若为避免该判定而移除全部技术路线图条目，
同一检查又会报出「manifest 中缺少技术路线图条目」。

### 冲突证据

同一技能内另外两个检查均明确支持 `html`：

- `check_roadmap_in_paper.py` 第 67 行的接受集合为 `{"drawio", "html", "imagegen", "image gen", "openai-imagegen"}`；
- `check_drawing_contract.py` 的 HTML 分支要求全部非数据绘图条目的 `generator` 必须为 `html`，
  并同时禁止 `手绘图/` 下出现 `.drawio` 源文件。

技能文档 `SKILL.md` 与 `references/drawing-pipeline.md` 也明确规定：
HTML 模式的技术路线图由内置 HTML 引擎按骨架池确定性生成，`template_id` 记录骨架池四类之一。
可见该检查的接受集合遗漏 `html` 属于实现遗漏，而非有意的模式限制。

### 处理

按该检查自身声明的意图「检查技术路线图记录与锁定模式一致」，将 `html` 补入接受集合，
使判定与锁定模式、技能文档及同族检查保持一致。改动仅为一个取值，未放宽任何版式或内容判据：

- 中文乱码检查 `cn_text_ok`
- 布局检查 `layout_ok`
- 内容检查 `content_ok`
- 论文回填检查 `paper_insert_ok`

上述四项判据全部保留，且本次运行的 5 张 HTML 图均逐张通过了 PDF 单页与矢量检查、
元素级几何自检（溢出 0、越界 0、重叠 0、对齐偏差 0）。

### 影响范围

- 未修改任何阶段注册表、启动器或状态契约；`项目状态.json` 中的 `registry_sha256` 与三个启动器哈希不变。
- 未跳过、未禁用任何检查，未伪造任何检查结论。
- 若后续技能版本已自行补入 `html`，本改动即为无操作。

## 缺陷二：门禁启动器指向过期技能副本

### 现象

`run_stage_gate.py --init` 生成的启动器只在以下两处查找门禁源：

- `~/.codex/skills/math-paper-huawei/scripts/checks/run_stage_gate.py`
- `~/.trae-cn/skills/math-paper-huawei/scripts/checks/run_stage_gate.py`

而本次会话加载的技能位于 `DSH_HOME` 下的 `skills/math-paper-huawei`。
两处副本均比会话加载的副本陈旧：缺少整个 HTML 矢量成图引擎、缺少优秀论文视觉校准，
且 `check_stage_contract.py` 的绘图模式接受集合仅含 `drawio` 与 `ai`，
导致卡片锁定的 `html` 模式被判为「项目状态缺少有效 drawing_mode」。

### 处理

先把两处陈旧副本各自改名备份，再从会话加载的技能目录整体同步覆盖，
使启动器解析到的门禁源与会话实际加载的技能版本一致。备份目录保留原文件以便回滚。

### 影响范围

- 未修改任何门禁逻辑；同步的是技能自身的更新版本。
- 同步后重新执行 `--init`，`registry_sha256` 随新版本更新，前序阶段标记为 stale 并已重跑通过。
