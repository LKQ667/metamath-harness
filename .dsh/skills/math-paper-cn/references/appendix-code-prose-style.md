# 附录代码净化与自然文风规则

## 附录代码

- 真实业务代码保持不变。论文附录使用真实 Python 脚本生成的等价净化副本，统一存入 `论文/附录代码/`。
- 复核配置固定为 `检查结果/附录代码复核.json`。`files` 记录真实源文件、附录文件、按函数限定名分组的 `rename_map`，以及必要的 `keep_long_names` 保留理由。
- 局部变量只在函数内部安全改名。参数、公共接口、全局量、导入名、函数名、类名、属性名、字典键和字符串不得修改。新名称应自然、简短、无冲突，原则上不超过 16 个字符。
- 遇到 `eval`、`exec`、`locals`、`globals`、`vars` 等名称反射时，该作用域不得自动改名。
- 附录代码去除普通注释和文档字符串，保留 shebang、编码声明及解释器必需指令；连续空行不得超过 2 行。
- 避免超长函数、过深嵌套、重复大段逻辑和无意义包装。此项由模型在第三轮自查中复核，不进行容易误判的复杂度硬判。
- 使用 `scripts/prepare_appendix_code.py --project <项目根目录>` 生成并验证附录副本。真实源文件哈希必须保持不变。
- 原版与净化版必须在隔离临时项目中使用同一命令运行。JSON 和 CSV 的结构及非数值字段必须完全一致，数值采用绝对和相对容差 `1e-9`；文本统一换行后精确比较，其他文件比较 SHA256。
- 命令失败、超时、输出缺失、结果不同或附录文件未被回归用例覆盖时，不得交付。

配置示例：

```json
{
  "tolerance": {"abs": 1e-9, "rel": 1e-9},
  "files": [
    {
      "source": "Q1/main.py",
      "appendix": "论文/附录代码/q1.py",
      "rename_map": {
        "solve": {
          "calculated_result_value": "res"
        }
      },
      "keep_long_names": {}
    }
  ],
  "runs": [
    {
      "name": "Q1回归",
      "command": ["{python}", "Q1/main.py"],
      "files": ["论文/附录代码/q1.py"],
      "outputs": [
        {"path": "results/final_results.json", "type": "json"}
      ],
      "timeout": 120
    }
  ]
}
```

## 自然文风

- 论文标题、摘要至“七、模型评价与改进”的可见论述禁止使用“首先、其次、然后、接着”组织段落。应直接写清逻辑关系，或借助因果、转折、条件、递进和指代自然衔接。
- 长短句交替使用。关键结论可以用短句收束，推导背景和限定条件用复合句展开，避免连续短句或整段句式同构。
- 第一人称只在团队行为、判断依据或客观取舍确有需要时少量使用，不为制造人工感强行插入。
- 正常论述中的 `（）`、`【】` 和裸 `[]` 每千字合计不得超过 4 组。公式、LaTeX 命令参数、引用命令、代码和参考文献不计入。
- 降低机械痕迹依靠可验证的命名、代码纯净度、运行等价性和自然表达，不承诺任何第三方 AI 检测器分数。
