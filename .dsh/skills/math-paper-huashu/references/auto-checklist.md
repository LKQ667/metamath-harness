# 全自动执行清单

## 总体原则

- 严格只围绕本技能阶段流程组织执行顺序：step0、step1、step2、step3、step4、step5。
- 不删除、不修改既有外部技能文件；仅在总工作流中将原 Step4 拆分为 Step4 内容组织和 Step5 最终交付。
- 默认目标是一次性跑完整个数学建模项目，直到输出可直接提交的论文成稿。
- 若用户只给出局部任务，则只执行对应阶段及其必要前置阶段，不跳过硬依赖。

## 一键执行顺序

### 0. 任务接收与范围确认

- 识别题目类型、赛题附件、数据文件、交付目标和截止要求。
- 判断是整题全流程，还是只做局部步骤。
- 若信息不足，先补齐最关键输入，再继续。

### 1. Step0 项目初始化与权威文献

- 自动探测并准备用户级 LaTeX，完成原字体烟雾编译；不得把“宿主机未安装”直接作为结束理由。
- 建立并确认的标准目录结构。
- 更新 AGENT.md、README.md、赛题索引和文件分区状态。
- 建立或确认 `data/` 目录，并在 `data/source_map.md` 中逐条登记每份数据的名称、用途、来源类型与具体依据；具体依据必须是 URL 或明确文件路径/附件名。
- 优先查找与赛题相关性最高的权威文献，顺序为：题目原文、官方附件、赛题直接参考文献、领域经典综述、与题目最接近的高质量论文。
- 记录“为什么选这篇文献、可用于哪一问、支持哪一段推导”。
- 运行 step0 硬门禁并保存阶段报告。

### 2. Step1 数据预处理与问题重述

- 运行 step1 硬门禁；无数据型赛题必须留下明确依据。
- 检查数据规模、变量类型、缺失值、异常值、重复值、分布和相关性。
- 做必要的清洗、变换和特征整理。
- 输出问题重述、已知条件、目标变量、约束关系和初步方法方向。
- 生成 1 到 2 张顶刊风格中文图作为数据预处理支撑。
- 至少确定 1 张数据预处理图最终进入论文正文。

### 3. Step2 单问建模设计

- 运行 step2 硬门禁，确认每问建模设计可独立交接。
- 对每个子问题比较 2 到 3 种候选方法。
- 选定主模型后，写出变量定义、目标函数、约束条件、求解思路和可行域。
- 为每问明确结果分析框架和图表建议。
- 若问题之间有关联，说明先后依赖关系和复用关系。

### 4. Step3 Python 代码实现

- 运行 step3 硬门禁，确认结果、代码、图片与流程图链路。
- 基于 step2 的模型和算法编写 Python 代码。
- 代码必须能复现建模逻辑、结果和图表。
- 真实业务代码保持不变；附录 Python 代码使用 `scripts/prepare_appendix_code.py` 生成等价净化副本，并完成 `检查结果/附录代码复核.json` 中声明的全部回归。
- Python 图优先调用本技能内置模板或核心 API，不使用外部 `Py-Nature` 路径。
- Python 图严格执行 `bar_policy`：禁用时源码零柱形 API；少用时同源 manifest 必须记录完整 `bar_exception`；正常仍按数据语义选图。每轮图型决策必须优先评估顶刊一区中文三维图可行性。
- 若图属于网络几何、时序网络、时空网络、动态社区或突发活动，先检查是否应使用新增模板，而不是套用旧模板后再人工硬改。
- 全文最终入文图片总数是否与 `figure_total` 一致，并按各问实际论证需要动态分配。
- 所有图在入论文前完成中文字体乱码检查，确认无方框、无问号、无缺字、无异常字体回退。
- Python 图必须同时导出 `svg + pdf + png`，并记录 `generator=python`、`template_id`、`chart_family`、`qa` 等 manifest 字段。
- 所有保留图全部达到顶刊科研绘图标准。
- 全文最终入文图片通常不少于 7 张，并至少检查是否覆盖：数据预处理 1 张、流程图 1 张、灵敏度分析 1 到 2 张、正文核心结果 5 张以上。
- 为每问输出 `Qn/result.md`，固定包含：问题目标、输入数据、核心假设、模型思路、关键公式通俗解释、运行命令、输出文件、核心数值结果、图表清单、结果解释、局限与下一问衔接。
- `scripts/` 只保留共享工具、总控脚本和检查脚本；每个实际 Q 目录必须有本问主脚本或包装脚本、模型说明和结果文件，禁止代码链路只集中在 `scripts/`。
- 每个实际 Q 目录必须有 `figures/` 子目录和至少 1 张本问相关图片；若确实不出图，必须在 `result.md` 写明“不出图理由”和“可复现结果来源”。

### 5. Step4 论文写作与内容组织

- 完成草稿编译并运行 step4 硬门禁。
- 摘要每个“针对问题X”是否仅加粗标签本身，每问是否另有重要算法、核心模型或主要结论的选择性强调；“关键词”标签和每个关键词是否分别加粗。
- 正文粗体是否仅落在决定性模型、关键判据、核心数值结论或最终推荐的短语上，且没有完整句、连续多句、整段或异常高密度加粗。
- 每问是否形成“贡献—证据—结论边界—评委质疑”内部主线，结果是否回扣模型承诺；是否删除重复定义、同义复述、空泛承接、模板化段式和宣传性措辞，同时保留必要推导与边界说明。
- 先读取参考论文，再统一正文结构与内容层级。
- 论文内容必须包含：摘要、关键词、问题重述、问题分析、模型假设、符号说明、模型建立与求解、敏感度分析、模型评价与改进。
- 论文正文必须严格遵守模板主结构：一、问题重述，二、问题分析，三、模型假设，四、符号说明，五、模型建立与求解，六、敏感度分析，七、模型评价与改进，八、参考文献；正文禁止新增主章节。
- 候选方法比较、体系结构、AI 痕迹检测、边界讨论、问题衔接、方法论启示、整体发现总结、数据-结果回扣、可复现性、运行顺序等不得作为正文主章节；可复现性和运行顺序必要时转移到 README、检查结果或附录说明。
- 论文允许自然留白，但禁止出现大半页空白；正文不得用强制分页、大段 `\vspace`、`\vfill` 或空图表占位制造留白。
- 正文从论文第一页开始，包括标题、摘要、关键词、问题重述至参考文献的全部内容；只排除附录中的支撑材料文件目录和代码。正文默认不少于 16 页，若用户明确要求更高页数，以用户要求为准；附录必须另起一页。
- 论文正文禁止出现实际字符 `•` 和 `☐`，不得用项目符号或复选框式无序列表组织正文。
- 若用户约定正文页数且正文不足，只能优先深化“模型建立与求解”，补变量定义、约束来源、推导链、适用条件、边界讨论、求解细节和结果解释，不得扩充参考文献、另增无关章节或堆砌套话。
- “模型建立与求解”必须用公式、参数定义、约束、算法步骤和结果解释支撑论证；页数不足时只补这一节的推导深度，不补废话主章节。
- “模型建立与求解”参考 `references/model-writing-b477.md` 做五章深化：任务目标、变量与适用条件、基础关系或定义修正、公式推导、目标/约束/递推或算法步骤、图表结果、结果解释与题目指标回扣必须形成连续链条。
- 摘要与关键词必须全部位于第一页，摘要有效文字至少 800 字、建议 850–1050 字；不得缩小字号、压缩行距或使用负间距规避页码门禁。
- 标题、摘要至“七、模型评价与改进”的可见论述不得出现“首先、其次、然后、接着”，括号密度每千字不得超过 4 组；句式长短、自然衔接和第一人称必要性必须人工复核。
- 灵敏度分析至少包含 1 到 2 张由 Python 生成的图，且图题、图例、坐标轴均为中文。
- 流程图、技术路线图或框架图必须走项目锁定的 Draw.io / AI 非数据绘图链路，并确认对应的 `.drawio` 源或 AI 提示词/成图与导出图已存入 `手绘图/`。
- 进入 Step4 前必须至少生成 1 张技术路线图或问题分析流程图，并把锁定模式的可追溯源、导出图、manifest 条目全部补齐。
- 技术路线图必须入论文正文，不能只保存在 `手绘图/`；临时草图不能作为最终路线图。
- 问题分析部分如需要技术路线图、流程图或可追溯结构框图，优先用 项目锁定的 Draw.io / AI 非数据绘图链路完成；若需要的是原理图、模型图、概念示意图，则必须由本技能内部生成对应 `手绘图/*.md` 提示词文件，并在文中写明该提示词存放相对路径；如项目已有 AI 绘图目录，可使用 `AI绘图/*.md` 或 `ai绘图/*.md`，不接受低质量临时截图直接入文。
- 正文禁止出现内部文件路径和绝对路径；除提示词相对路径 `手绘图/*.md`、`AI绘图/*.md`、`ai绘图/*.md` 外，不得显示项目内部路径。

### 6. Step5 排版编译与最终交付

- 运行 step5 全量回归；只校验 PDF 和全部报告。不得调用 Word 生成或转换流程；项目中已有 `.docx` 保持不动，不检查、不删除且不影响完成。
- 先读取参考论文，再统一模板、参考文献、附录和最终导出版式。
- 附录必须完整纳入全部核心代码，并在模板中做整洁排版，不允许仅保留“见某目录/某文件”的占位式附录；代码块内部必须是纯代码，禁止 Markdown 围栏、标题符号、装饰分隔线、注释和连续大量空行。
- 附录净化代码必须位于 `论文/附录代码/`，所有文件均被回归用例覆盖；原版和净化版的命令、输入、输出结构及关键数值必须一致。
- 附录“支撑材料文件目录”只写代码名称和重要 Excel 结果名称，允许纯名称保留 `.py`、`.xlsx` 等后缀；禁止写绝对路径、相对路径、目录路径或“见某文件夹”。
- 最终交付前完成三轮自查：第一轮内容与数据链，第二轮论文与版式链，第三轮代码与复现链，并写入 `检查结果/三轮自查.md`；自查必须覆盖正文符号、支撑材料目录、摘要页约束、B477 式公式推导链、图表解释链、结果回扣链、普通柱状图必要性、顶刊一区中文三维图可行性评估和正文页数是否达标，其中摘要页约束必须写明一页内、尽量写满、`abstract:end` 和编译页码复核；正文边界必须记录正文起始页、正文结束页、附录起始页、正文实际页数，并明确参考文献计入正文、支撑材料目录与代码附录排除、附录另起页。
- 论文必须以技能内置 `assets/templates/main.tex + JXUSTmodeling.cls` 为基座增量替换；默认不生成目录，禁止 `\tableofcontents`、`main.toc` 和 `\maketitle`，必须使用模板原生 `abstract` 环境。

## 自动化检查点

- `results/final_results.json` 是否存在，并且论文、摘要、README、result.md、CSV/JSON 与其关键数值一致。
- `data/` 目录是否存在，`data/source_map.md` 是否存在，且每份数据都写明了 URL 或具体文件依据；未记录来源的数据不得进入建模、图表或正文。
- Q 目录是否保留本问主脚本、包装脚本、模型说明或结果文件，避免所有代码集中在 `scripts/`。
- 每个 Q 目录是否存在 `result.md` 和本问 `figures/`，且 `result.md` 能让未参与建模的人读懂目标、方法、结果、图表和复现路径。
- 摘要是否以自然语言为主；如确需公式，是否必要、简洁且未破坏华数杯首页版式。
- 摘要是否限制在第一页内，是否保留 `\label{abstract:end}`，且摘要长度足以接近写满第一页。
- `figures/manifest.json` 是否存在，是否记录每张入文图的源文件、导出文件、用途、章节、分辨率和检查状态。
- Python 图是否通过专项检查：导出格式齐全、SVG 文字可编辑、manifest 字段完整、中文字体检查通过。
- Python 源码是否通过策略门禁：禁用时零柱形 API；少用时每个调用都有同源完整 `bar_exception`。
- 三轮自查是否记录“顶刊一区中文三维图可行性评估”。
- 流程图是否同时保留 所选模式的可追溯源和论文可用导出图，且已通过中文乱码、内容和版式检查。
- 技术路线图是否已经在论文 `main.tex` 中引用，manifest 是否记录 Python 生成方式、布局检查和论文回填检查。
- 若正文涉及原理图、模型图、概念示意图且判断为“需要图”，则必须核对对应 `手绘图/*.md` 是否存在且非空，并核对文中是否已经明确显示对应 `手绘图/xxx图.md` 路径；这属于最终交付门禁。若某段明确判断为“不需要图”，则不要求为凑数创建提示词文件。
- 论文是否严格基于华数杯内置模板体系，且没有目录页或 `\maketitle`，并保留原生 `abstract` 环境。
- 论文正文是否严格遵守模板主章节白名单，是否没有额外 `\section` 和废话主章节。
- “模型建立与求解”是否包含足够公式推导、目标/约束、求解步骤和结果解释，而不是只堆结果图或套话。
- 核心图表是否解释其服务的公式来源、算法步骤、结果结论或题目指标，而不是只给图名。
- 论文正文是否没有大半页空白风险、强制分页、大段 `\vspace`、`\vfill` 或空图表占位。
- 正文是否从第 1 页开始、包含参考文献、在附录前结束，附录是否另起下一页；正文页数是否不少于 16 页，若用户自定义更高正文页数，是否达到更高目标。
- 论文正文是否没有实际字符 `•` 和 `☐`。
- 正文是否没有内部文件路径和绝对路径，且只放行提示词相对路径。
- 附录支撑材料文件目录是否只保留代码名称和重要 Excel 结果名称，且没有路径、目录或“见某文件夹”写法。
- 附录代码是否为纯代码，是否没有 Markdown 围栏、标题符号、装饰分隔线、注释或连续大量空行。
- 真实源代码哈希是否未改变，附录局部改名是否未触及参数、公共接口、全局量、导入名、函数名、类名、属性名、字典键和字符串；等价回归是否全部通过。
- 论文是否通过机械连接词和括号密度门禁，三轮自查是否记录自然衔接、句式变化和第一人称必要性。
- `检查结果/三轮自查.md` 是否存在，且包含内容与数据链、论文与版式链、代码与复现链三轮结论，并覆盖正文符号、支撑材料目录、摘要页约束、正文章节白名单、废话主章节清理、模型建立与求解深化证据、B477 式公式推导链、图表解释链、结果回扣链、普通柱状图必要性、顶刊一区中文三维图可行性评估和正文页数是否达标；摘要页约束必须写明一页内、尽量写满、`abstract:end` 和编译页码复核。
- LaTeX log 是否不存在 `Undefined control sequence`、图片缺失、字体缺字、交叉引用未更新等硬风险。
- 项目文件中是否没有 `F:\`、`C:\Users`、`/home`、`/Users` 等硬编码绝对路径前缀。
- 交付目录中是否没有 `.venv`、`__pycache__`、临时 preview、debug 图和乱码文件名。
- README.md 是否包含运行命令、依赖环境、最终结果、复现步骤、异常处理记录、外部新增数据和外部文献。
- AGENT.md 是否包含阶段状态自动更新区，并明确禁止编造数据、结果、文献和代码。
- `文献/source_map.md` 是否记录来源链接、可信等级和支撑章节。
- 目录结构是否完整。
- 文献是否足够权威且和赛题直接相关。
- 数据预处理是否真实、可复现、无篡改。
- 模型是否与数据特征匹配。
- 代码和图表是否可直接用于论文。
- Python 图的中文字体是否存在乱码、丢字或显示回退异常。
- 全文图量是否严格等于 `figure_total`，且没有重复图、换色变体或空洞凑数图。
- 全文图片数量与结构是否合理，是否至少覆盖数据预处理图、流程图、灵敏度图和 5 张以上正文核心图。
- 锁定模式流程图的 `.drawio` 源或 AI 提示词/成图是否都已落到 `手绘图/`。
- 附录代码是否完整收录且排版整洁，而不是只写文件路径说明。
- 论文是否像人工撰写的国一作品，而不是模板化拼接。

## 脚本化检查

创建项目目录后的第一条项目命令：

```powershell
python "<技能目录>\scripts\checks\run_stage_gate.py" --project "<项目根目录>" --init
```

此后每阶段只运行项目内固定入口：

```powershell
python "<项目根目录>\scripts\checks\run_stage_gate.py" --project "<项目根目录>" --stage stepN
```

最终交付前运行：

```powershell
python "<项目根目录>\scripts\checks\verify_delivery.py" --project "<项目根目录>"
```

任一命令退出码非 0 必须停止。最终检查必须生成 `check_report.json`、`check_report.md` 和 `delivery_attestation.json`；缺任一文件或验证输出不是 `ok: true`，不得交付。

## 终止条件

- 用户要求的整题交付物已完成。
