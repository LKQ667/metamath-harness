# 工作流

## 一键执行原则

- 严格只围绕本技能阶段流程组织执行顺序：step0、step1、step2、step3、step4、step5。
- 不删除、不修改既有外部技能文件；仅在总工作流中将原 Step4 拆分为 Step4 内容组织和 Step5 最终交付。
- 默认从题目与文献开始，一路推进到论文成稿；只有在用户明确要求局部任务时才局部收束。
- 任何阶段发现信息缺口，都先补齐关键前置条件，再继续后续阶段。

## Step0: 项目初始化

- 先运行 `scripts/latex/latex_runtime.py probe --project <项目根目录>`，仅做无网络快速探测；缺少 LaTeX 时记录延后安装并继续，不在 step0 下载。step4 首次草稿编译前由 `latex_runtime.py compile` 按 `references/latex-bootstrap.md` 自动自举并直接验证实际论文编译。
- 必须建立并确认标准目录：赛题/、文献/、data/、Q1/、Q2/、Q3/、Q4/、灵敏度分析/、数据预处理/、手绘图/、摘要/、论文/。
- 生成或更新 AGENT.md、README.md，保证项目规则、数据文件和模块状态统一。
- 根据实际赛题问数动态建立 Q 目录；若题目只有三问，不硬建空 `Q4/`。已存在但不适用的空目录需标注“不适用”或在最终交付前清理。
- 建立 `results/` 和 `检查结果/`，其中 `results/final_results.json` 是唯一最终结果源。
- `data/` 目录用于存放原始数据、外部补充数据、下载数据、清洗前副本以及数据说明文件；禁止把来源不明的数据直接放入建模链路。
- Step0 必须在 `data/` 下维护 `source_map.md`，逐条记录每份数据的名称、用途、来源类型、具体依据；具体依据至少要写一个外部链接，或明确写出对应文件路径/附件名，例如 `赛题/附件1.xlsx`、`data/raw/orders.csv`。
- 若数据为派生数据，`data/source_map.md` 还必须写明上游源文件以及生成脚本、处理说明或结果来源；未记录来源的数据不得进入建模、图表或正文。
- 保留 `scripts/` 作为共享工具、总控脚本和检查脚本目录；每个实际问题目录 `Q1/`、`Q2/` 等必须最终保留本问主脚本或包装脚本、模型说明和结果文件，禁止只有 `scripts/solve_all.py` 或 `scripts/plot_figures.py` 而 Q 目录为空。
- 每个实际问题目录 `Qn/` 最终必须包含 `README.md`、`result.md`、本问主脚本或包装脚本、`figures/` 子目录；若赛题有 5 问，就覆盖 `Q1/` 到 `Q5/`，不把第五问漏在总控脚本或总图目录里。
- 一般在 step0 处必须先查找权威、与赛题相关性最高的文献，优先级顺序为：题目原文、官方附件、赛题直接参考文献、同行综述或经典论文、与题目最接近的高质量论文。
- 创建项目根目录后先从已加载 Skill 目录运行 `run_stage_gate.py --init`，安装项目内固定门禁入口；完成本阶段后运行项目内 `scripts/checks/run_stage_gate.py --project <项目根目录> --stage step0`，未通过不得进入 Step1。

## Step1: 引入与数据预处理

- 完成数据处理后运行 step1 阶段门禁；数据型赛题必须有预处理入口和派生数据，无数据型赛题必须记录题面依据。
- 对原始数据做 EDA：规模、变量类型、缺失值、异常值、重复值、分布、相关性。
- 输出数据预处理结论、问题重述和方法筛选理由。
- 至少生成 1 到 2 张顶刊风格中文图。
- 数据预处理阶段最终至少有 1 张图进入论文正文，用于支撑数据质量、分布特征或预处理必要性说明。
- 所有缺失、超范围、裁剪、滤波、去趋势、归一化、外部新增数据等处理行为必须写入对应 `audit.json`，正文不得跳过这些处理记录。

## Step2: 单问分析建模

- 完成后运行 step2 阶段门禁；每个实际 Q 目录必须形成目标、输入、假设、变量、公式、约束、方法和验证设计。
- 每个子问题都要先比较 2 到 3 种候选方法，再锁定一种主方法。
- 公式必须完整，变量定义、目标函数、约束条件、可行域都要写清楚。
- 结果分析要包含合理性验证、边界讨论和必要的可视化建议。

## 论证与写作纪律----使推理更具深度

- Step2 建模时，先给 4 到 6 步主线骨架，再展开公式、算法和结果；不要一上来堆长推导。
- 锁定主方法时，必须写清为什么选它，以及为什么不是另一个同样合理的候选方法。
- Step2 与 Step3 的推导、证明或公式解释中，先定义变量、目标函数、约束和适用范围；若调用外部定理、标准公式或现成结构，显式标出调用点与调用目的。
- 凡是从前一步跳到后一步可能让读者补链的地方，补一句过渡说明，避免只写“显然”“由此可知”。
- Step4 组织论文内容时，默认把“概念解释层”和“正式论证层”分开写；解释层先帮助读者理解，正式层再给出严格表述，不让同一段同时承担两层任务。
- 若任务目标偏严格证明或高分论文，优先补严谨性：条件、引用来源、适用边界、过渡句；确认这些齐全后，再补篇幅、修辞和装饰性表达。

## Step3: 代码实现

- 用 Python 复现 step2 选定的方法。
- Python 图统一使用本技能内置绘图子系统：`scripts/plotting/py_nature_core.py`、`scripts/plotting/template_registry.py` 与 `assets/templates/py-figures/`。
- 先按 `references/py-chart-selection.md` 判定任务语义与图型，再决定是否调用内置模板；不要先画柱状图再补理由。
- 当任务落在网络几何、动态社区、时序网络、时空网络或突发活动时，优先使用新增分支和新增模板，不把它们强行回退为普通 `network_resilience` 或 `trend_confidence`。
- 所有最终结果先写入 `results/final_results.json`；result.md、CSV、JSON、论文表格和摘要只能引用该唯一结果源。
- 全文最终入文图片总数严格服从项目锁定的 `figure_total`（默认 15 张）；按各问信息密度、结果层次和论文篇幅动态分配，不设置机械的每问配额，不得重复凑图。
- 所有候选图在入选前都要检查中文标题、坐标轴、图例、标注和注释是否乱码，是否出现缺字、方框、问号或字体回退不一致；未通过检查的图必须先修复字体配置再重新导出。
- Python 图导出必须至少包含 `svg + pdf + png` 三种格式；其中 SVG 必须保留可编辑文字，PDF 必须保留 TrueType 文本，PNG 用于预览与入文核对。
- Python 图的 manifest 条目必须补充 `generator=python`、`template_id`、`chart_family` 和 `qa` 状态，供专项检查脚本验证。
- 最终保留的图全部满足顶刊科研绘图标准。
- 从全篇统筹看，以 `figure_total` 为最终数量目标；默认结构优先覆盖数据预处理、流程图、灵敏度分析、正文核心结果和必要原理图，具体分配结合论文节奏与版面密度动态裁剪。
- 每问输出 `Qn/result.md`，写清问题目标、输入数据、核心假设、模型思路、关键公式通俗解释、运行命令、输出文件、核心数值结果、图表清单、结果解释、局限与下一问衔接。
- 真实业务代码不得为附录展示而改写。附录 Python 代码按 `references/appendix-code-prose-style.md` 生成等价净化副本，并通过原版与净化版隔离运行回归；无法运行或结果不一致时不得进入 Step4。
- 完成后运行 step3 阶段门禁；结果源、逐问代码与结果、Python 图和 Step4 前流程图契约必须全部通过。
- 每问的主脚本、包装脚本或结果说明必须同步落入对应 Q 目录；`scripts/` 中的总控脚本只能调用这些分问链路，不能成为唯一代码和结果来源。
- 每个 `Qn/figures/` 至少保存本问 1 张相关生成图；根目录 `figures/` 可保留论文汇总图，但不能替代 Q 目录的本问图片追溯。确实不出图时，必须在 `Qn/result.md` 写明“不出图理由”和“可复现结果来源”。
- 若使用内置模板，图源脚本优先放在对应 `Qn/` 下，本技能内模板仅作为复用范式与调用基座，不替代项目本问追溯链路。

## Step4: 论文写作与内容组织

- 摘要按实际问题逐段组织，每段只将“针对问题X”标签本身加粗，再选择性加粗该问的重要算法、核心模型和主要结论；“关键词”标签与每个关键词分别加粗。正文只加粗决定性模型、关键判据、核心数值结论和最终推荐中的短语，原则上不加粗完整句，禁止连续多句、整段或高密度机械强调。
- 写作前逐问锁定贡献、证据、结论边界和评委可能质疑点；写作后检查结果是否验证模型承诺、论断是否有公式/数据/图表支撑。删除同义复述、空泛承接、宣传性措辞和机械段式，但保留变量定义、数据来源、推导桥梁、适用条件、误差说明与边界讨论；不得触发或依赖外部 `humanizer`、`paper-spine`。
- 进入 Step4 前必须至少生成 1 张按锁定模式生成的技术路线图或问题分析流程图；Draw.io 模式的 `.drawio`、2× PNG、SVG、PDF，或 AI 模式的提示词、严格可解码 PNG，以及 manifest 条目缺一不可。
- 论文允许自然留白，但禁止出现大半页空白；正文不得用 `\newpage`、`\clearpage`、大段 `\vspace`、`\vfill` 或空图表占位制造留白。
- 正文从论文第一页开始，包括标题、摘要、关键词、问题重述至参考文献的全部内容；只排除附录中的支撑材料文件目录和代码。模板必须使用 `body:start`、`body:end`、`appendix:start` 标记边界，附录必须另起一页。
- 论文正文禁止出现实际字符 `•` 和 `☐`，不得用项目符号或复选框式无序列表组织正文。
- 若用户约定正文页数且正文不足，必须优先深化“模型建立与求解”：补变量定义、约束来源、推导链、适用条件、边界讨论、求解细节和结果解释；禁止新增无关章节、堆砌套话或重复图表凑页数。
- 论文正文必须严格遵守模板主结构：一、问题重述，二、问题分析，三、模型假设，四、符号说明，五、模型建立与求解，六、敏感度分析，七、模型评价与改进，八、参考文献；正文禁止新增主章节，禁止把候选方法比较、体系结构、AI 痕迹检测、边界讨论、问题衔接、方法论启示、整体发现总结、数据-结果回扣、可复现性、运行顺序等作为独立 `\section`。
- 页数不足时只能深化“五、模型建立与求解”，重点补公式、推导、参数定义、约束、算法步骤、结果解释；不得通过扩充参考文献、新增章节或套话凑页，可复现性和运行顺序不进入正文，必要时转移到 README、检查结果或附录说明。
- “五、模型建立与求解”的深化写法参考 `references/model-writing-b477.md`，每问优先按“任务目标 -> 变量与适用条件 -> 基础关系或定义修正 -> 公式推导 -> 目标/约束/递推或算法步骤 -> 图表结果 -> 结果解释与题目指标回扣”推进；B477 只作为写法参考，不改变模板主章节。
- 技术路线图必须插入 `论文/main.tex` 正文，不能只存在于 `手绘图/`。临时路线草图只能辅助思考，最终路线图必须来自 项目锁定的 Draw.io / AI 非数据绘图链路，并通过中文乱码、标签错位、重叠裁切和论文缩放检查。
- 对原理图、模型图、概念示意图，先判断是否真的需要图；不要为了“看起来完整”硬塞配图。只有当文本单靠公式或叙述难以快速解释结构、机制、状态迁移、因果链或空间/时序关系时，才进入内嵌提示词链路。
- 原理图、模型图、概念示意图不要求额外触发外部技能，直接由本技能内部生成 `手绘图/xxx图.md`，并在文稿合理位置写明该提示词存放相对路径；如项目已有 AI 绘图目录，可使用 `AI绘图/*.md` 或 `ai绘图/*.md`。若判断需要图，这一项属于硬约束，缺少路径显示或缺少对应提示词文件都不能进入 Step5。
- 完成后运行 step4 阶段门禁；运行器先执行草稿编译，再检查摘要、正文、引用、图表、模板、结构和文风。
- 正文禁止出现内部文件路径和绝对路径；除上述提示词相对路径外，不得在正文中显示 `Q1/`、`scripts/`、`data/`、`results/`、`论文/` 等项目内部路径。

- 内嵌提示词链路默认生成 2 到 4 张不重复图片，并按分工拆开：结构图说明“是什么”，机制图说明“如何作用”，时序/空间/关系图说明“如何演化或传播”，必要时再补 1 张支撑视角。
- 若当前段判断为“不需要图”，必须明确保持无图，不允许为了凑图量生成空洞占位或重复 prompt。
- 论文内容必须包含：摘要、关键词、问题重述、问题分析、模型假设、符号说明、模型建立与求解、敏感度分析、模型评价与改进。
- 摘要优先使用自然语言写背景、方法、关键结果和结论；华数杯不套用国赛“摘要禁止公式”硬门，但公式只在确有必要且不破坏首页版式时使用。
- 摘要与关键词必须全部位于第一页；关键词后保留 `\label{abstract:end}`，编译后页码必须为 1。摘要有效文字至少 800 字，建议 850–1050 字，在不跨页且不缩小字号、行距或使用负间距的前提下尽量铺满。
- 摘要必须少量加粗最关键结果，但不能整段加粗。
- 正文和摘要应控制括号密度，避免 AI 味堆叠。
- 论文标题、摘要至“七、模型评价与改进”的可见论述禁止“首先、其次、然后、接着”，`（）`、`【】` 和裸 `[]` 每千字合计不超过 4 组；句式层次与第一人称必要性按 `references/appendix-code-prose-style.md` 执行。
- 灵敏度分析必须包含 1 到 2 张由 Python 生成的图，图题、图例、坐标轴均为中文。
- 流程图或技术路线图必须按项目锁定模式生成；Draw.io 模式保留 `.drawio`、SVG、PDF、2× PNG，AI 模式保留提示词与可解码成图，统一存入 `手绘图/` 并写 manifest 后再插入论文。
- 流程图、技术路线图、问题分析图和模型框架图统一走本技能内置的项目锁定 Draw.io / AI 非数据绘图链路，并在 `figures/manifest.json` 中记录可追溯源、导出图、入文章节和检查状态。
- 问题分析部分如果需要技术路线图、流程图、模块框图或要求可追溯源的结构图，统一走项目锁定的 Draw.io / AI 非数据绘图链路；若需要的是原理图、模型图、概念示意图，则按锁定模式生成提示词或成图，禁止直接用粗糙截图替代最终图。
- 论文里的图片必须兼顾美观与信息密度，优先按单栏/双栏版式做尺寸与留白适配，不要求把所有生成图片都塞进正文。

## Step5: 排版编译与最终交付

- 运行 step5 阶段门禁或兼容入口 `run_all_checks.py`；只要求 PDF、源文件、三轮自查和全部注册检查通过即可把项目状态写为 `completed`。不得调用 Word 生成或转换流程；已有 `.docx` 不检查、不删除且不参与完成判定。
- 默认先检查并使用技能内置模板 `assets/templates/main.tex`。进入 Step5 时先读取实际采用的模板，再决定正文、摘要、参考文献、附录和图表如何落版。
- 先读取并对齐参考论文版式，再开始排版正文。
- 最终论文必须补齐参考文献和附录，并与正文、摘要、关键词、图表形成统一模板体系。
- 附录必须完整收录全部核心代码，不能只写文件路径提示；代码说明放在代码块外，代码块内部必须是纯代码，不得出现 Markdown 代码围栏、标题符号、装饰分隔线、注释或连续大量空行，并按模板做分页与空白控制，保证排版整洁。
- 附录代码应从真实脚本生成等价净化副本，并在 `检查结果/附录代码复核.json` 记录源文件、附录文件、改名映射、运行命令、输出文件和前后哈希；语义和结果必须一致，不要求与源脚本文本逐字相同。
- 附录“支撑材料文件目录”只写代码名称和重要 Excel 结果名称，允许纯名称保留 `.py`、`.xlsx` 等后缀；禁止写绝对路径、相对路径、目录路径或“见某文件夹”。
- 若用户已经在项目模板 `模板/main.tex` 中做过本地微调，后续排版必须在原结构上增量修改，禁止重新生成一个风格不兼容的新 `main.tex`。若项目里还没有模板，则必须先从技能内置 `assets/templates/main.tex` 落地到项目，再继续增量修改。
- 任何与标题字号、编号、摘要缩进、关键词样式、参考文献标题、附录标题相关的调整，都必须优先复用 `JXUSTmodeling` 已有接口，如 `\biaoti{}`、`\keyword{}`、原生 `abstract`、`thebibliography` 与 `appendixx`，避免手写出第二套样式系统。
- 华数杯论文默认不生成目录；禁止 `\tableofcontents`、`main.toc`、“目录”页和普通 `\maketitle`，必须保留 `JXUSTmodeling` 提供的原生 `abstract` 环境。允许内容创新，但必须以华数杯模板为基座增量替换。
- 最终交付前必须完成三轮自查并写入 `检查结果/三轮自查.md`：第一轮检查内容与数据链，第二轮检查论文与版式链，第三轮检查代码与复现链；自查必须覆盖正文符号、支撑材料目录、摘要页约束、B477 式公式推导链、图表解释链和结果回扣链，摘要页约束必须写明一页内、尽量写满、`abstract:end` 和编译页码复核；正文边界复核必须记录正文起始页、正文结束页、附录起始页、正文实际页数，并明确参考文献计入正文、支撑材料目录与代码附录排除、附录另起页，三轮均通过后才能进入最终提交。
