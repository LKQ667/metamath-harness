# 求解与验证细则

本文件只约束用户授权的实际求解。只做初探时不执行实验，不生成测量值或通过声明。

## 比较对象和证据状态

先按 `candidate-selection.md` 的完整作答标准区分候选、基线、变体与验证。可复用原模型内核、共同随机数或公共预处理，但记录实际共享范围；共享关键实现的两次运行不能宣称完全独立的代码核验。

每条路线使用稳定标识和角色字段记录，不因调参新增推荐编号。比较时保证题意、数据、评价口径和预算可比；改变目标或放宽约束的结果只作情景对照。每项结论分别标注推导支持、已有结果未复核、新计算已验证或未验证，不能用某个共享模块测试通过代替整条路线验证。

## 任务适配

| 类型 | 最低有效比较 | 必要的风险检查 |
|---|---|---|
| 预测/统计学习 | 朴素基线、同一划分、验证集调参、封存测试集最终评估 | 时间滚动或分组划分；预处理仅拟合训练集；误差分层、区间覆盖、过拟合 |
| 运筹优化 | 同一目标和约束、可比预算、可行性检查；小规模精确解或有效界 | 约束残差、上下界/gap、多起点分布、离散取整后的可行性 |
| 机理/动力学仿真 | 可解释基准、观测拟合或独立验证 | 量纲、守恒、边界、参数可辨识性、步长/网格收敛和数值稳定性 |
| 综合评价/决策 | 权重与归一化依据、外部效度或已知案例 | 权重扰动、排名稳定性、尺度依赖；无真实标签时不报告虚构准确率 |

题目可能跨类型，分别检查并说明耦合误差。题目若不提供数据，可进行题目条件下的解析计算与有依据的数值求解；合成数据只能用于单元验证或明确的模拟实验，不冒充赛题观测。

## 防止局部最优与选择偏差

1. 先识别凸性、离散结构、可分解性和问题规模；有可靠精确法时优先用它建立基准，不默认启发式越复杂越好。
2. 非凸/组合问题按需要使用分散起点、不同随机种子、重启、扰动邻域、全局探索后局部精修。随机算法默认至少五个独立种子；预算不足写明样本不足，不从单次成功推断稳定性。
3. 记录最优值、中位数、离散程度、可行率与耗时，保持候选预算一致或解释成本差异。多起点不证明全局最优；只有证明、枚举或可靠求解器证书才能使用该表述，否则写“当前预算内最佳已知可行解”。
4. 全局最优 gap 必须用有效界和明确公式，分母接近零时用绝对 gap；无界时不编造 gap。多目标展示非支配解与选点依据。
5. 参数调优和路线选择只使用训练/验证信息。不可因看过测试结果而不断修改并继续称其为独立测试；已经发生则重新划分可行的外层验证或披露偏差。

## 增益必须能归因

- 每项创新都需要针对性的消融：去掉它、替换为标准做法，或在同样预算下比较。多组件至少比较基线、单组件与最终组合，避免把多花的计算量当方法增益。
- 对关键输入、估计参数、约束松紧和权重做有业务意义的扰动；必要时检验结构假设变化。不要机械地全部正负 10%，范围必须有来源或清楚标为情景。
- 有重复样本时给适用的不确定性区间或配对比较；自相关序列不直接用独立样本 bootstrap。确定性结果不伪造统计显著性。
- 相对提升写清基线、方向、分母和单位；基线为零时使用绝对差。改善低于噪声或计算容差时不夸大。

## 实验记录与复现

每次运行至少保存 run_id、candidate_id、输入路径与 SHA-256、代码版本或指纹、参数、seed、划分/情景、命令、依赖版本、预算、耗时、退出状态、目标值、可行性、验证指标、输出路径。失败指标为 null 并保留原因，不填零。数值 JSON 不输出 NaN/Infinity。

最终结果指向保留的运行，表格与说明从同一数值源产生，展示舍入不改变底层值。用独立约束/指标计算检查推荐解，避免只信求解器的成功标记。可验证时以小规模枚举、解析特例或替代实现交叉检查核心逻辑；不要求为每段代码机械补测试。
