# DSH 底层升级与本地功能保护

适用于能读写文件、运行命令的任意 Agent，不依赖特定 IDE、MCP、Goal 工具或子代理。默认项目根为含 `.dsh/` 的仓库根；用户指定其他根目录时使用该目录。只审计时停在报告，不安装、不重启；创建本技能不代表授权执行升级或发布。

## 1. 建立本轮事实源

- 读取根目录 `维护范式.md` 全文、`README.md` 的本地改造清单及升级/启动章节；检索 `goal修复记录.md` 的相关完整条目，包括后续恢复与撤销记录。首次使用还要浏览全部历史标题，发现摘要漏项。每轮读取当前文件，不凭技能内版本号认定现状。
- 三文档分别提供维护规则、功能范围和演变证据；冲突时结合带日期的后续记录、当前源码、安装解析与实际行为核实，记录差异，不默默择一。GOAL 编号曾复用，使用日期加标题定位。
- 读取 [保护地图](references/protection-map.md)，将其中风险加入本轮清单；再对照 `plugins/`、全部本地 Preset/Skill、活动 Profile 的依赖、bundle、patch、override，补齐未登记功能。不得把这张地图当成穷尽清单。
- 从 [官方 Tags](https://github.com/deepseek-ai/deepseek-harness/tags) 核实目标标签及提交，核对发布说明、npm 精确包版本和中间版本破坏性变化。用户未指定版本时按其 RC 更新意图选择已发布 RC，记录选择；不能把最新 alpha 当作 RC，也不使用浮动 `latest`。
- 若用户指定的记录只有无法解析的标识，说明“正文不可读取”，保留待核实项；不声称已经读懂该记录。继续可独立完成的审计，影响迁移判断的信息缺失时不切换生产。

## 2. 保护与隔离预演

在本轮独立目录保存一份简短 `upgrade-report.md`，复用已有证据目录即可，不创建重复台账。最小记录：旧/新 DSH 与工具链版本、目标提交、三文档哈希、实际入口/Profile/DSH_HOME、备份位置，以及下表。

| 功能 | 源码/资产与接线 | 升级前行为 | 新版冲突与迁移 | 验收证据 | 回退方法 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |

每个现有功能单独一行；状态使用“待验 / 通过 / 阻塞 / 已获用户同意停用”。文件存在、插件数量相同、HTTP 200 都不能替代行为验收。

备份本地所有权源码、测试、脚本、资产、全部自定义 Preset/Skill、Profile 接线与补丁文件、维护文档，并生成 SHA-256 清单和备份回读校验。先识别真实路径和 Junction，不跟随链接递归展开；不要整目录复制 `.dsh`。不能统一排除 `lib/`：无可重建源码的本地派生包按保护地图保留。

凭据、会话、日志、数据库、用户工作区不作为源码迁移源，不放入备份报告或发行物；保留原位。新版可能自动迁移用户存储时，先核实格式与回退兼容性，使用合成数据预演；需要额外私有数据备份时遵守用户授权边界，不能借升级读取或复制秘密。

在独立安装目录、独立 DSH_HOME/Profile、空闲回环端口预演，禁止复用生产数据路径、凭据或写入中的数据库。先证明纯官方新版可启动，再逐项接回扩展。生产覆盖前停止已确认属于目标 DSH 的写入进程；不能只凭端口号杀进程。

## 3. 按行为迁移

以“旧官方基线、目标官方基线、本地差异”三方比较；无 Git 的目录用精确版本包、文件差异和哈希，不假设仓库存在。未知来源的旧修改先登记和调查，不覆盖抹除。

- 官方包和内置 Preset 使用新版；本地源码按新版 API 最小适配并重建。所有本地 Preset 对照新版 `standard`，保留专属 persona/工具及现有手动触发语义。
- Profile 在新版基础上重做最小接线，同时核对 `package.json`、`cordis.patch.yml`、`pnpm-workspace.yaml`、`patches/`、lockfile。bundle 自激活与主 patch 不得重复 insert；有配置覆盖时沿用同 id。
- 第三方差异保留来源、精确版本/提交、许可证及本地补丁。优先配置/外置适配，其次版本绑定 patch；不得以重装上游原包替代本地派生版。
- 热补丁先核实新版是否已有等效能力；未吸收则用在册幂等脚本针对新版产物重放，锚点失配先适配脚本，不复制旧 `client.js`。补丁退役须有等效行为证据并更新登记。
- 检查实际依赖解析位置和包版本，不能把 missing peer 或 `assertNever` 报错直接判为插件不可用。`file:` 复制与 Junction 分别处理；复制未刷新时定向 remove/add 并恢复原接线顺序、正斜杠 specifier，逐文件对比构建与安装哈希。Junction 重建后同样核验。
- 版本门默认拒绝未知版本。隔离候选可定向加入目标版本以完成兼容验证，但不开放通配符、不绕过检查；未通过前不把候选门提交为生产兼容基线。

## 4. 验收后切换

按保护地图完成识图、深链及其他清单项的真实行为验证；运行适用的 build/check/test、环境与论文 E2E、peer 检查、脱敏 dump-config、HTTP 和真实浏览器验证。记录旧基线既有失败、新增失败及未验证项，不能沿用历史通过数量。

预演通过才更新活动环境，并在实际入口下复测：安装哈希、插件单例、设置/卡片、浏览器控制台、快捷方式热启动与冷启动、换 token 后认证。识图与深链不得仅凭预演或单元测试宣布恢复。真实付费调用按已有授权执行，缺授权则明确未验证，不以模拟结果冒充。

无法解决时优先恢复单个适配或临时禁用故障插件，保留新版官方可用与本地源码/数据；这是故障隔离，不是“全部功能保留”的完成状态。不得默默删除识图、深链等功能来换取启动成功。保留最后已验证环境和恢复材料，不用旧包覆盖新版安装树掩盖故障。

## 5. 收口与下次复用

全清单通过后才更新兼容基线；未验证、阻塞、未经用户同意的功能减少均不算完成。按三文档职责最小更新现状和风险，在 `goal修复记录.md` 追加带日期、实际文件、验证、回退的记录，不改写历史。

交付简短版本结论、可读 diff、改动文件、功能清单结果和剩余事项。下次以三文档及上轮报告定位差异，只读相关历史正文，不复制全部历史进技能。源码、开发安装、便携版、公开 staging 分别标注实际验证版本；只有用户要求分发时才构建/发布，不能把本地验收等同发行验收。
