# 手绘图后续生成与回填说明

本目录保存非数据图的可追溯源与论文可用导出图。项目必须先锁定 `Draw.io 绘图` 或 `AI 全自动绘图`；Draw.io 模式只为概念类图保留 `手绘图/*.md` 提示词，AI 模式无需二次确认，逐份自动生图并回填。

选路必须写入项目根目录 `项目状态.json` 的 `drawing_mode`，并与 `figures/manifest.json` 顶层记录一致；两处均锁定后不得静默切换。

AI 模式按下列顺序全自动工作；生图能力不可用或重试后仍不合格时硬阻断交付：

1. 先完整阅读并理解赛题原文和附件、`论文/main.tex`、`数据/data.md`、`results/final_results.json`、各 `Qn/result.md` 与核心代码、`figures/manifest.json`、全部 `手绘图/*.md`，确认赛题任务、论文段落、代码和结果链已经对齐。
2. 逐一读取 `手绘图/*.md`，确认每份提示词文件且只能包含 `## 服务段落`、`## 生成图片的提示词`、`## 硬约束` 三块；重点核对服务段落中的放置位置、论文依据、对应问题、所用知识与符号来源，以及提示词正文中的 `布局原型`、`阅读方向`、`主色家族`、`区分点`。
3. 若提示词要求图中出现符号或公式，必须核对论文符号说明、模型公式、`results/final_results.json` 和对应 `Qn/result.md`，不得自行创造符号、改写公式或补未经论文定义的变量。
4. 先吸收当前 skill `assets/reference-pictures/` 中内置 AI 论文主图与截图的双轮蒸馏规则，再调用当前环境可用的 `Image Gen/imagegen`；不得依赖外部技能目录，不得改变论文事实、数据来源、变量含义、年份、地名、工程量、数值、文献或结论，也不得把流程治理词渲染为图内可见文字。
5. 立即调用 `Image Gen` 或 `imagegen`，为每份概念类提示词各生成一张候选图，并另生成至少一张不占概念图配额的流程类图。
6. 生成图片后，按提示词对应的服务段落自动回填到 `论文/main.tex` 的合理位置，在原提示词路径附近插入或替换为 `figure + includegraphics`，并保留原 `手绘图/xxx图.md` 相对路径，便于追溯提示词来源。
7. 回填时优先使用与提示词同名的图片文件，例如 `手绘图/洪水机制原理图.md` 对应 `手绘图/洪水机制原理图.png`；若生成多个版本，文件名必须能看出图名和版本。
8. 回填后在 `检查结果/AI绘图回填清单.md` 记录提示词文件、生成图片文件、回填章节、回填位置、是否保留提示词路径和是否重新编译论文。

硬约束：

- 禁止编造数据、文献、信息或任何内容。
- 禁止虚构地名、年份、工程量、数值、文献、数据来源和论文未给出的事实。
- 图片只能表达论文已经给出的机制、模型、变量关系和可核验结果，不能新增未经核验的结论。
- 图中的符号、公式、变量名、单位和数值必须与论文符号说明、模型公式、唯一结果源和对应问题结果说明一致。
- 生图模型必须读取当前 skill `assets/reference-pictures/` 作为视觉参考，只能借鉴框架、结构、排版、思维链、配色和阅读路径，不得复制其中的具体内容、数据、标签、结论、实体名称或数据关系。
- 若 `手绘图/*.md` 中出现 `禁止编造`、`禁止造假`、`结果复核`、`三轮复核`、`不得抄袭`、`可复现`、`可信输出` 等流程词，只允许出现在 `## 硬约束`，且必须明确“不渲染为图内可见文字”。
- 若提示词依据不足，应先回到论文正文、数据台账或结果源补足依据；不能用图片生成弥补事实缺口。
