# yatai-cn 全自动执行清单

## 总体原则

- 以 `math-paper-cn` 的 step0 到 step4 为基础，但所有执行落在亚太杯中文赛项目与 `yatai-cn` skill 内。
- 不修改 `math-paper-cn` 原 skill。
- 默认目标是一次性推进到可提交论文；局部任务也必须补齐必要前置条件。
- 信息缺口先查权威来源，官网优先；禁止编造数据、文献、信息或任何内容。

## 一键执行顺序

### 0. 任务接收与范围确认

- 识别赛题、附件、已给数据、缺失数据、交付目标和截止要求。
- 若赛题未给数据或数据不足，先拆题并列出数据缺口，再全网搜索权威数据。

### 1. Step0 项目初始化与数据台账

- 建立并确认 `数据/`、`赛题/`、`文献/`、`数据预处理/`、`Q1...Qn/`、`灵敏度分析/`、`手绘图/`、`摘要/`、`论文/`、`results/`、`检查结果/`。
- `手绘图/` 必须包含 `README.md`，说明按项目锁定模式交付非数据图；AI 模式在充分阅读赛题、论文、数据台账、结果源、Qn/result.md、核心代码、manifest 和提示词后，直接调用当前环境的 `Image Gen/imagegen` 生成图片并回填论文，不依赖外部技能目录。
- 在 `数据/` 下维护 `data.md` 和 `data.xlsx`；`data.md` 写可点击链接与数据作用，`data.xlsx` 存放原始索引、清洗后数据、字段说明和来源映射。
- 赛题附件、本地文件、外部数据和派生数据均必须登记来源、用途、处理记录和适用问题。
- 优先查找与赛题相关性最高的权威文献，并在 `文献/source_map.md` 记录来源链接、可信等级和支撑章节。

### 2. Step1 数据预处理与问题重述

- 检查数据规模、变量类型、缺失值、异常值、重复值、分布和相关性。
- 做必要的清洗、变换、特征整理和审计记录。
- 输出问题重述、已知条件、目标变量、约束关系和初步方法方向。
- 至少生成 1 到 2 张中文论文级图作为数据预处理支撑。

### 3. Step2 单问建模设计

- 对每个子问题比较 2 到 3 种候选方法。
- 选定主模型后，写出变量定义、目标函数、约束条件、求解思路和可行域。
- 若问题之间有关联，说明先后依赖关系和复用关系。
- 每问先形成 4 到 6 步主线骨架，每步写清输入、依据和输出；公式推导必须变量先定义、条件先说明、结论再落地。
- 写作前维护 `检查结果/推理论证复核.md`，逐问复核主线骨架、变量定义、公式推导链、假设来源、上下文衔接、边界讨论和结果回扣。

### 4. Step3 Python 代码实现

- 基于 step2 的模型和算法编写 Python 代码。
- Python 图统一使用本技能内置绘图子系统和 `assets/templates/py-figures/` 模板。
- 先按 `references/py-chart-selection.md` 判定任务语义与图型，不为方便默认画柱图。
- Python 图硬约束禁止非必要普通一维、二维柱状图；若确需使用，manifest 必须记录完整 `bar_exception`。每轮图型决策必须优先评估顶刊一区中文三维图可行性。
- 所有保留图必须导出 `svg + pdf + png`，并在 `figures/manifest.json` 中记录 `generator=python`、`template_id`、`chart_family`、`paper_ready` 和 `qa`。
- 每个实际 `Qn/` 必须有 `result.md`、主脚本或包装脚本、`figures/` 子目录；确实不出图时必须在 `result.md` 写明理由和可复现结果来源。

### 5. Step4 论文写作与排版

- 摘要每个“针对问题X”是否仅加粗标签本身，每问是否另有重要算法、核心模型或主要结论的选择性强调；“关键词”标签和每个关键词是否分别加粗。
- 正文粗体是否仅落在关键模型、决定性判据、核心数值结论或最终推荐的短语上，且没有完整句、连续多句、整段或异常高密度加粗。
- 每问是否形成“贡献—权威数据或计算证据—结论边界—评委质疑”内部主线，结果是否回扣模型承诺；是否删除重复定义、同义复述、空泛承接、模板化段式和宣传性措辞，同时保留数据来源、必要推导与边界说明。
- 论文以用户指定的 APMCM 中文赛模板为首选模板，缺失时使用 `assets/templates/main.tex`。
- 论文正文必须包含摘要、关键词、问题重述、问题分析、基本假设、符号说明、模型建立与求解、灵敏度分析、模型评价与改进、参考文献、附录。
- 除参考文献、附录和代码外均视为正文；正文默认不少于 16 页，若用户明确要求更高页数，以用户要求为准。
- 进入正文前必须至少生成 1 张按锁定模式生成的技术路线图或问题分析流程图；锁定模式的可追溯源、论文可用导出图和 manifest 条目缺一不可。
- 技术路线图必须插入 `论文/main.tex` 正文，临时草图不能作为最终路线图。
- 锁定模式流程图 manifest 的 QA 必须包含视觉密度、箭头路由、节点重叠、文字适配和风格非死板检查，避免大色块、长斜箭头、文字过小和层次不清。
- 原理图、模型图、概念示意图为必交内容，生成 2 到 4 份 `手绘图/xxx图.md` 提示词并在文中显示相对路径；提示词必须包含图类型、赛题任务、服务段落、对应问题、论文依据、核心变量/对象、变量/符号来源、代码或结果来源、结构分区、视觉层级、颜色与版式、禁止元素、禁止编造、可核验来源/数值约束，且正文每行只显示 1 个提示词路径。若图内需要符号或公式，必须声明与论文符号说明、模型公式、唯一结果源和 Qn/result.md 一致。Draw.io 模式只保留概念类提示词；AI 模式无需二次确认，逐份自动生成并回填，失败时硬阻断交付。
- 用户约定页数且正文不足时，必须把增量内容写回对应问题的“模型建立与求解”，并在 `检查结果/推理论证复核.md` 记录“模型建立与求解深化项”和具体深化位置；禁止新增弱相关凑页章节。
- 摘要必须严格限制在第一页内并尽量写满第一页，建议 800-1000 字；摘要必须到关键词结束，关键词后正文第一节必须另开新页；正文禁止实际字符 `•`、`☐` 和会生成圆点的 `itemize` 环境，附录代码必须完整、纯净、可读且无注释。
- 最终交付前完成三轮自查：第一轮内容与数据链，第二轮论文与版式链，第三轮代码与复现链，并写入 `检查结果/三轮自查.md`；自查必须覆盖正文符号、支撑材料目录、摘要页约束、普通柱状图必要性、顶刊一区中文三维图可行性评估和正文页数是否达标。
- 每次生成或更新 `论文/main.tex` 后立即 XeLaTeX 编译；修复到 `main.log` 无硬错误、`main.pdf` 与 `main.aux` 存在，并写入 `检查结果/latex_compile_record.md`。

## 自动化检查点

- `数据/data.md` 是否存在，是否含可点击 URL、来源机构、访问日期、字段说明、数据作用和清洗记录。
- `数据/data.xlsx` 是否存在，是否包含 `数据清单`、`原始数据索引`、`清洗后数据`、`字段说明`、`来源映射`。
- `results/final_results.json` 是否存在，且论文、摘要、README、result.md 与其关键数值一致。
- Q 目录是否保留本问主脚本、结果说明和本问图片追溯。
- `figures/manifest.json` 是否记录每张入文图的源文件、导出文件、用途、章节、分辨率和检查状态。
- Python 图是否通过导出格式、SVG 可编辑文字、manifest 字段和中文字体检查。
- Python 图是否没有非必要普通一维、二维柱状图；若使用普通柱状图，是否具备完整 `bar_exception`。
- 三轮自查是否记录“顶刊一区中文三维图可行性评估”。
- 锁定模式流程图是否同时保留 所选模式的可追溯源和论文可用导出图。
- 锁定模式流程图是否有 manifest QA 字段：`visual_density_ok`、`edge_routing_ok`、`node_overlap_ok`、`text_fit_ok`、`style_not_stiff_ok`。
- `手绘图/README.md` 是否存在，是否明确 `手绘图/*.md`、`Image Gen/imagegen`、AI 模式自动生成图片和回填、生成前完整理解赛题/论文/代码/结果链、禁止编造、失败硬阻断，以及 Draw.io 模式只交付概念类提示词。
- 若正文显示 `手绘图/*.md`、`AI绘图/*.md` 或 `ai绘图/*.md` 提示词路径，对应文件必须存在且非空，并通过提示词严谨度门禁；多个路径不得出现在同一正文长行。
- AI 绘图提示词是否绑定赛题、论文段落、对应 Qn、变量/符号来源、代码或结果来源；涉及符号或公式时是否声明与论文一致。
- 论文是否严格基于 APMCM 中文赛模板体系，且没有目录页、`\maketitle` 或普通 `abstract` 环境。
- `论文/main.tex` 生成后是否已编译，`main.log/main.aux/main.pdf` 是否存在，`检查结果/latex_compile_record.md` 是否记录无报错闭环。
- 论文正文是否没有大半页空白、强制分页、大段 `\vspace`、`\vfill`、空图表占位，且编译后的 PDF 任一正文页没有超过 1/3 页高的连续空白带。
- 正文页数是否不少于 16 页；若用户自定义更高正文页数，是否达到更高目标。
- 附录支撑材料文件目录是否只保留数据预处理代码、灵敏度分析代码、Q1-Q4 代码和题目明确要求的结果 `.xlsx/.xls/.csv`；结果文件是否有 `检查结果/题目要求结果清单.md` 支撑。
- 附录支撑材料文件目录是否没有“文件/目录”“位置”“路径”列名或“见某文件夹”写法。
- 附录代码文件是否只包含完整 Q1-Q4 代码和完整灵敏度分析代码，且没有总控、数据预处理、绘图、检查、配置或结果文件内容。
- `检查结果/推理论证复核.md` 是否覆盖 7 个必需部分且没有待补项。
- `检查结果/三轮自查.md` 是否包含三轮结论并明确最终通过，且覆盖正文符号、支撑材料目录、摘要页约束、普通柱状图必要性、顶刊一区中文三维图可行性评估和正文页数是否达标；摘要页约束必须写明一页内、尽量写满、`abstract:end` 和编译页码复核。
- README.md 和 AGENT.md 是否包含运行命令、复现步骤、数据真实性规则和阶段状态。
- 交付目录中是否没有 `.venv`、`__pycache__`、临时 preview、debug 图和缓存文件。

## 脚本化检查

最终交付前运行：

```powershell
python <DSH_HOME>\skills\yatai-cn\scripts\checks\run_all_checks.py --project <项目根目录>
```

检查结果必须写入 `检查结果/check_report.json` 和 `检查结果/check_report.md`。任一检查失败时，不得进入最终提交。
