# 亚太杯中文赛工作流

## Step0 项目初始化

- 建立或确认目录：`赛题/`、`数据/`、`文献/`、`数据预处理/`、`Q1/` 到 `Qn/`、`灵敏度分析/`、`手绘图/`、`摘要/`、`论文/`、`results/`、`检查结果/`。
- `数据/` 必须包含 `data.md` 和 `data.xlsx`；用户硬约束原文中的 `data.xlsl` 保持原文不改，实际落地使用标准 Excel 工作簿 `data.xlsx`。
- `data.md` 记录数据来源、链接、用途、字段、处理记录和可信等级。
- `data.xlsx` 保存原始索引、清洗后数据、字段说明和来源映射。
- `手绘图/README.md` 必须在初始化阶段创建，用于说明依据项目锁定模式读取赛题、论文、数据台账、结果源、Qn/result.md、核心代码、manifest 和 `手绘图/*.md`；AI 模式直接调用当前环境的 `Image Gen/imagegen` 生成图片并回填论文，不依赖外部技能目录。
- 优先整理赛题原文、官方附件、官方说明和优秀论文样式。

## Step1 引入与数据预处理

- 先拆题：背景、目标、输入、输出、约束、评价指标、时间空间尺度、缺失数据。
- 再搜索数据：官网、政府部门、国际组织、行业主管机构、国家或地区统计平台优先，论文补充数据只作为备选。
- 所有下载或手工整理的数据都必须保留来源、访问日期和处理记录，并同步写入 `数据/data.md` 与 `数据/data.xlsx`。
- 禁止造假，禁止胡编乱造，禁止编造数据、文献、信息或任何内容。
- 数据缺失、异常、单位换算、插值、标准化、筛选等行为必须写入审计记录。
- 至少生成 1 张中文数据预处理图，最终是否入文由论文叙事决定。

## Step2 单问建模

- 每问至少比较 2 种候选方法，说明为什么选择主模型。
- 变量、参数、目标函数、约束条件、可行域和求解流程必须明确。
- 如果数据不足，继续查找权威数据；仍无法获得时，只能建立有依据的假设并标注影响范围。

## 论证与写作纪律：使推理更具深度

- Step2 建模前先压出 4 到 6 步主线骨架，每步写清输入、依据和输出，再展开公式、算法和结果。
- 公式推导必须先定义变量、参数、目标函数、约束和适用范围；不得直接抛公式或用“显然”“容易得到”跳过关键环节。
- 引用外部定理、标准公式或已有模型时，必须说明它在本文中的调用点、调用目的和适用条件。
- 问题之间有关联时，明确上一问的结果如何成为下一问的输入、约束或评价指标。
- 用户约定正文页数且页数不足，或论述单薄时，只能深化“模型建立与求解”：补变量定义、约束来源、推导链、适用条件、边界讨论、求解细节、结果解释和上下文衔接，不得堆砌套话、重复图表，或新增“综合解释”“图表策略”“落地建议”“创新性总结”“迁移应用讨论”“质量控制复核”等弱相关章节。
- 最终写入 `检查结果/推理论证复核.md`，覆盖主线骨架、变量定义、公式推导链、假设来源、上下文衔接、边界讨论和结果回扣。

## Step3 代码实现

- Python 脚本按问题分区放入 `Qn/`，`scripts/` 只放共享工具和总控脚本。
- 所有最终结果先写入 `results/final_results.json`；论文、摘要、README 和各问 result 只能引用该唯一结果源。
- `Qn/result.md` 必须说明输入数据、核心假设、模型思路、运行命令、输出文件、图表清单和局限。
- 图表必须检查中文字体、分辨率、图例、坐标轴和论文缩放可读性。
- Python 图先按 `references/py-chart-selection.md` 判定任务语义与图型，再调用内置绘图模板；默认导出 `svg + pdf + png`。

## Step4 论文写作与排版

- 摘要按实际问题逐段组织，每段只将“针对问题X”标签本身加粗，再选择性加粗该问的重要算法、核心模型和主要结论；“关键词”标签与每个关键词分别加粗。正文只加粗关键模型、决定性判据、核心数值结论和最终推荐中的短语，原则上不加粗完整句，禁止连续多句、整段或高密度机械强调。
- 写作前逐问锁定贡献、权威数据或计算证据、结论边界和评委可能质疑点；写作后检查结果是否验证模型承诺、论断是否有来源/公式/数据/图表支撑。删除同义复述、空泛承接、宣传性措辞和机械段式，但保留数据来源、变量定义、推导桥梁、适用条件、误差说明与边界讨论；不得触发或依赖外部 `humanizer`、`paper-spine`。
- 优先使用用户指定的 APMCM 中文赛项目模板；缺失时使用 skill 内置 `assets/templates/main.tex`，并保持 APMCM 中文赛模板风格。
- 正文包含摘要、关键词、问题重述、问题分析、模型假设、符号说明、模型建立与求解、灵敏度分析、模型评价、参考文献、附录。
- 进入正文前必须至少生成 1 张按锁定模式生成的技术路线图或问题分析流程图并落入 `手绘图/`；Draw.io 模式保留 `.drawio`、2× PNG、SVG、PDF，AI 模式保留提示词与严格可解码 PNG，两者都必须有 `figures/manifest.json` 条目。
- 技术路线图必须插入 `论文/main.tex` 正文，不能只存在于 `手绘图/`；manifest 的 QA 必须记录配色、视觉密度、箭头路由、排版错位、中文乱码、节点重叠、文字适配和风格非死板检查。
- 原理图、模型图、概念示意图是必交内容；必须生成 2 到 4 份不重复的 `手绘图/xxx图.md` 提示词，并在文稿合理位置写明该相对路径。每份提示词必须且只能包含 `## 服务段落`、`## 生成图片的提示词`、`## 硬约束` 三块，不得使用 `# 标题`、额外 H2/H3。`## 服务段落` 写放置位置、论文依据、对应问题、所用知识与符号来源；`## 生成图片的提示词` 只写真正给图像模型的绘图提示词，必须显式写出 `参考图组：当前 skill 的 assets/reference-pictures/`、`借鉴点：框架 / 结构 / 排版 / 思维链 / 配色`、`仅借鉴形式，不复制具体内容、数据、标签、结论`，以及 `布局原型`、`阅读方向`、`主色家族`、`区分点`，且不得包含 `禁止编造`、`禁止造假`、`结果复核`、`三轮复核`、`不得抄袭`、`可复现`、`可信输出` 等流程污染词；`## 硬约束` 只放硬约束与负面约束，若出现上述流程词，必须明确“不渲染为图内可见文字”。同批提示词在布局原型、阅读方向、主色家族、区分点中至少 2 项显式不同，且至少覆盖原理图、模型图、概念示意图三类；若图内需要符号或公式，必须声明与论文符号说明、模型公式、`results/final_results.json` 和 `Qn/result.md` 一致。正文排版使用“AI 绘图提示词：”独立小段，后续每行 1 个 `\texttt{手绘图/xxx图.md}`，不使用圆点列表，不把多个路径挤在同一长行。Draw.io 模式只交付概念类提示词；AI 模式不等待二次确认，逐份自动调用当前环境的生图能力并回填，重试后仍不可用或不合格时硬阻断。后续提示词复核和生图模型都必须先读取当前 skill `assets/reference-pictures/`，不允许转而读取 skill 外部图片路径。
- 正文禁止实际字符 `•`、`☐` 和 `itemize` 圆点项目符号；列举内容改写为自然段、编号句、`enumerate` 或表格。
- 参考文献按正文引用顺序排列，网上资源必须写 URL 和访问日期。
- 附录完整收录核心代码，不能只写“见文件”。
- 附录代码必须是纯代码，禁止注释、Markdown 围栏、装饰分隔线和连续大量空行。
- 摘要必须严格限制在第一页内，并尽量写满第一页，建议 800-1000 字；摘要页必须到关键词结束，关键词和 `\label{abstract:end}` 后正文第一节必须另开新页；编译后的 `main.aux` 中必须复核摘要结束页码和“问题重述”等第一节页码，第一节不得仍在第 1 页。
- 附录“支撑材料文件目录”只写纯文件名和简短说明，只允许数据预处理代码、灵敏度分析代码、Q1-Q4 代码，以及题目明确要求提交或输出的结果 `.xlsx/.xls/.csv`；结果文件必须在 `检查结果/题目要求结果清单.md` 中列出题目原文依据、允许文件名、对应问题、是否必须提交或输出。
- 附录“附录代码文件”只放完整 Q1-Q4 代码和完整灵敏度分析代码；禁止放总控脚本、数据预处理脚本、绘图脚本、检查脚本、配置脚本或结果文件，且代码必须无注释。
- 每次生成或更新 `论文/main.tex` 后必须立即在 `论文/` 下运行 XeLaTeX；按最小改动修复到 `main.log` 无硬错误、`main.pdf` 和 `main.aux` 存在，并在 `检查结果/latex_compile_record.md` 记录编译命令、修复轮次和最终无报错结论。
- 最终交付前完成三轮自查并写入 `检查结果/三轮自查.md`：第一轮内容与数据链，第二轮论文与版式链，第三轮代码与复现链；摘要页约束必须记录一页内、尽量写满、`abstract:end` 和编译页码复核。
- 最终运行 `scripts/checks/run_all_checks.py --project <项目根目录>`。
