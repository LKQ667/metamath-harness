# 顶刊风格与流程图规范

## 图表总体要求

- 所有图中文字使用中文。
- 所有 Python 导出的图在提交前都要人工或程序化检查中文是否乱码，重点检查标题、图例、坐标轴、注释、色条标签和保存后的位图/PDF 显示效果。
- 所有 Python 图统一走本技能内置的 `scripts/plotting/` 链路，不依赖外部 `Py-Nature` 路径。
- 默认使用专业、克制的配色，避免默认彩虹色和高饱和渐变。
- 图表要适配论文单栏或双栏宽度，缩小后仍清晰可读。
- 输出优先使用 300 dpi 以上，流程图优先 SVG 或 PDF。
- Python 图必须同时导出 `svg + pdf + png`；SVG 要保留文字节点，PDF 要保留 TrueType 文本，PNG 用作快速核图。
- Q1 到 Q4 每问进入论文的图量严格控制在 2 到 4 张，图的选择要服务于建模叙事，避免同质图、重复图和仅换配色的变体图。
- 全文入文图片通常不少于 7 张，但不追求“全放进去”；默认至少覆盖数据预处理 1 张、流程图 1 张、灵敏度分析 1 到 2 张、正文核心结果 5 张以上，并根据版面效果和说服力动态取舍。
- 所有入文图片都要做论文级排版适配，关注宽高比例、图注长度、上下留白、与正文衔接位置，不允许出现“图很好但塞进论文后很挤”的情况。
- 论文允许自然留白，但禁止大半页空白；不得用强制分页、大段 `\vspace`、`\vfill` 或空图表占位制造版面空洞。编译后的 PDF 任一正文页不得出现超过 1/3 页高的连续空白带。用户约定页数且正文不足时，只能深化“模型建立与求解”的变量定义、公式推导、约束来源、求解细节、边界讨论和结果解释，不用综合解释、迁移应用、质量控制、套话或重复图表凑页数。
- 论文正文禁止出现实际字符 `•`、`☐` 和会生成圆点项目符号的 `itemize` 环境；需要分层表达时使用自然段、编号句、`enumerate` 或表格。
- Python 图硬约束禁止非必要普通一维、二维柱状图；只有“类别很少、必须零基线、核心任务是绝对高度比较”同时成立时才允许例外，并必须在 manifest 中记录 `bar_exception`。优先使用 line+band、tornado、Sobol 热图、Pareto、network+curve、phase portrait、contour/quiver、interval/lollipop、hero/support 多面板；强烈建议优先评估顶刊一区中文三维图，如三维曲面、三维散点、三维轨迹、三维场和三维响应面。
- 对网络几何、多尺度社区、时空 Chronnet 和突发活动场景，新增 `network_curvature_multiscale`、`spatiotemporal_chronological_network`、`temporal_bursty_activity` 三类模板，并要求同一方法跨 panel 不换色、同一色条跨 panel 不改端点语义。

## 原理图 / 模型图 / 概念示意图

- 这三类图由本技能内部直接生成提示词，提示词统一写入 `手绘图/`，并在文中显示对应 `手绘图/xxx图.md` 相对路径即可；如项目已有 AI 绘图目录，可使用 `AI绘图/*.md` 或 `ai绘图/*.md`。每份提示词必须且只能包含 `## 服务段落`、`## 生成图片的提示词`、`## 硬约束` 三块，不得使用 `# 标题`、额外 H2/H3。正文不得显示其他内部文件路径或绝对路径。
- `## 服务段落` 必须写明放置位置、论文依据、对应问题、所用知识与符号来源；`## 生成图片的提示词` 必须显式写出 `布局原型`、`阅读方向`、`主色家族`、`区分点`，并据此把同批 2 到 4 张图至少在 2 个维度上拉开。
- `## 生成图片的提示词` 还必须显式写出 `参考图组：当前 skill 的 assets/reference-pictures/`、`借鉴点：框架 / 结构 / 排版 / 思维链 / 配色`，以及“仅借鉴形式，不复制具体内容、数据、标签、结论”。
- `禁止编造`、`禁止造假`、`结果复核`、`三轮复核`、`不得抄袭`、`可复现`、`可信输出` 等流程治理词不得进入 `## 生成图片的提示词`，也不得作为图内可见标签；如需约束，只能放在 `## 硬约束` 并明确“不渲染为图内可见文字”。
- `手绘图/README.md` 必须说明双模式协议：Draw.io 模式不生成概念类图，AI 模式在理解赛题、论文、数据、结果源、各问结果、核心代码和 manifest 后逐份自动调用 `Image Gen/imagegen` 生成并回填，不等待二次确认。
- 每份提示词必须贴合具体赛题和论文段落，写明对应问题、变量/符号来源、代码或结果来源；若图内出现符号或公式，必须与论文符号说明、模型公式、唯一结果源和 `Qn/result.md` 保持一致，不得为了视觉效果自造公式、变量或数值。
- 正文排版使用独立提示词小段，每行只显示 1 个 `\texttt{手绘图/xxx图.md}`；禁止把 2 到 4 个提示词路径挤在同一行，也不使用圆点列表展示。
- 图像目的先于美观：先讲清对象、结构、机制、路径和关键关系，再谈配色和构图。
- 默认采用白底、克制、中文顶刊风格，避免海报感、赛博感、营销感和大面积噪点。
- 语义配色保持稳定：主对象或主方法优先稳重蓝系，背景结构优先灰系，强调点只允许少量暖色，不让同一语义在同组图里反复换色。
- 默认按 `hero/support` 分层组织：主画面负责“对象或结构”，支撑区域负责“机制、局部关系、时序逻辑或空间逻辑”。
- 同组 2 到 4 张图必须分工明确，不允许只换标题、换视角或换配色做重复图。
- 除必要标签外，避免在图内塞入大段解释文字；能靠结构表达的内容，不要靠说明书式文字堆叠。

## 锁定模式流程图

- 默认使用本技能内置的项目锁定 Draw.io / AI 非数据绘图链路；`scripts/plotting/python_flowchart.py` 仅用于旧项目兼容，不作为新项目非数据图来源。
- 进入 Step4 前必须至少完成 1 张技术路线图或问题分析流程图；未生成 所选模式的可追溯源时，最终检查直接失败。
- 问题分析图、技术路线图、模块关系图、求解流程图统一走 项目锁定的 Draw.io / AI 非数据绘图链路，不用临时截图、PPT 截图或一次性草图充当最终稿。
- 先搭结构，再调样式。
- 默认使用分层泳道、短连接、低饱和语义配色和稳定留白，避免大色块、长斜箭头、文字过小和均匀堆砖式布局。
- 使用圆角矩形、少量强调色、清晰箭头、统一间距；节点大小跟文字量适配，缩进论文宽度后仍能读清。
- 结构建议采用自上而下或从左到右的单主线：输入 -> 预处理 -> 建模 -> 求解 -> 结果 -> 结论。复杂分支使用分列、分组或泳道，不用多条长箭头硬连。
- 箭头必须清晰、不穿节点、不跨层乱连、不重叠、不裁字；节点之间保留稳定间距，避免箭头贴边或从框体内部穿过。
- 不要堆叠太多装饰元素，不要使用调试草图风格。
- 绘制完成后同时保留锁定模式的可追溯源和导出图，统一落到 `手绘图/`，便于跨电脑复用与论文替换。
- 锁定模式的可追溯源和论文用图必须同存于 `手绘图/`：Draw.io 模式保留 `.drawio`、2× PNG、SVG、PDF，AI 模式保留提示词与严格可解码 PNG；产物不得只散落在 `figures/` 且无 manifest 追溯。
- 技术路线图必须在 `论文/main.tex` 中用 `\includegraphics` 正式入文，并保证缩放后标签可读、图注明确、上下留白正常。
- 每张流程类图必须在 manifest 统一记录生成器、模板、源、导出、提示词源、就绪状态、导出状态、视觉复核状态和完整 QA；生成器必须与锁定模式一致。
- 入文前必须完成至少两层检查：第一层检查锁定模式的可追溯源、manifest 和导出图是否齐全；第二层检查论文插入适配、缩放可读性、标签不裁切、内容无乱码、布局无明显错位。

## 论文排版参考
- 必须严格参考用户指定的 APMCM 中文赛模板；缺失时使用 `assets/templates/main.tex` 作为备用模板。
- 若用户提供官方或赛项模板文件，以用户指定模板为准；不得把固定本机路径写入 workflow 规则。
- 标题、摘要、关键词、一级二级三级标题、参考文献和附录的层级关系要稳定一致。
- 摘要必须限制在第一页内，并尽量写满第一页；沿用模板标题、摘要、关键词排版，关键词后保留 `\label{abstract:end}`，随后正文第一节必须另开新页，禁止“问题重述”和摘要同页。
- 论文中的图表说明要简洁，避免模板腔。
- 附录代码区要像正式论文成品：全部代码完整收录，listing 标题统一，说明文字简洁，分页自然，避免大段代码块把页面挤坏；代码块内部必须是纯代码，禁止 Markdown 围栏、标题符号、装饰分隔线、注释和连续大量空行。
- 支撑材料文件目录只写允许项纯文件名：数据预处理代码、灵敏度分析代码、Q1-Q4 代码、题目明确要求提交或输出且已在清单中放行的 `.xlsx/.xls/.csv` 结果文件；不得写路径、目录、“位置”列、“文件/目录”列、“见某文件夹”、数据台账、唯一结果源、总控脚本、图片、PDF 或临时产物。
