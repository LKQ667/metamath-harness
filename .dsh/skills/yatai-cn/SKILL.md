# yatai-cn

## 定位

这是面向亚太杯数学建模中文赛项目的专业技能。它以 `math-paper-cn` 的全流程为基础，但在独立目录中工作，禁止修改原始 `math-paper-cn` skill。

## 不可变硬约束原文

以下内容是用户指定的不可变硬约束，执行本技能时必须逐字遵守；其中 `data.xlsl` 按原文保留，实际可执行数据工作簿仍使用标准 Excel 文件 `数据/data.xlsx`。

1.## Step0: 项目初始化 需要新加文件夹：数据，里面放置data.md（分别详细写明数据来源————必须是可以点击的链接，数据作用），还有一个data.xlsl(存放数据)
2.math-paper-cn是基础，亚太杯中文赛往往不会给你提供数据，必须全网搜索，## Step1: 引入与数据预处理 这一步必须要先把题目理清楚再搜索全网权威数据，官网优先，绝对禁止造假，禁止胡编乱造！！！并再data.md、data.xlsl补充。硬约束：# 禁止编造数据，禁止编造文献,禁止编造信息，禁止编造任何内容
3.后面的步骤可能遇到数据不知的情况，请继续搜索全网权威数据，官网优先，绝对禁止造假，禁止胡编乱造！！！并再data.md、data.xlsl补充
4.把用户指定项目模板中的 `main.tex` 作为亚太杯专用模板，并参考用户指定的 APMCM 中文赛论文模板 DOCX。

## 总原则

- 禁止修改本项目之外的任何 `math-paper-cn` Skill 副本。
- 全程中文表达，代码关键字和必要英文术语除外；图片、图注、代码注释、Excel、流程图文字必须全部中文。
- 禁止编造数据、禁止编造文献、禁止编造信息、禁止编造任何内容；所有数据、文献、方法、结论和图表必须可追溯。
- 亚太杯中文赛经常不提供完整数据；缺数据时必须先理清题目，再全网搜索权威数据，官网、政府部门、国际组织、行业主管机构、国家或地区统计平台优先。
- 所有新增外部数据必须同步写入 `数据/data.md` 和 `数据/data.xlsx`，并记录来源链接、作用、字段、访问日期和处理记录。
- 无法核验的数据只能作为候选线索，不得进入模型、结果或论文。
- 每个项目正式做题前必须询问并锁定一次 `Draw.io 绘图` 或 `AI 全自动绘图`，写入 `项目状态.json` 与 `figures/manifest.json`；旧项目缺记录时补问，禁止猜测或混用。Python 数据图保持既有链路；非数据图严格执行 `references/drawing-pipeline.md`。
- Python 图硬约束禁止非必要普通一维、二维柱状图，只有在“类别很少、必须零基线、核心任务是绝对高度比较”同时成立时才允许例外，并必须在 `figures/manifest.json` 写明 `bar_exception` 必要性记录；强烈建议优先评估顶刊一区中文三维图，不是必须采用，但每轮图型决策都要判断是否可用三维曲面、三维散点、三维轨迹、三维场或三维响应面提升信息密度，并在三轮自查中记录“三维图可行性评估”。
- 原理图、模型图、概念示意图是必交内容；必须生成 2 到 4 份不重复提示词。Draw.io 模式只交付概念类提示词；AI 模式逐份自动调用 `Image Gen/imagegen` 生图并回填，不等待二次确认，另至少生成一张流程类图；生图不可用或 QA 不合格时硬阻断交付。每份提示词文件必须且只能包含 `## 服务段落`、`## 生成图片的提示词`、`## 硬约束` 三块；不得使用 `# 标题`、额外 H2/H3。`## 服务段落` 只写放置位置、论文依据、对应问题、所用知识与符号来源；`## 生成图片的提示词` 只写真正给图像模型的科学绘图提示词，必须显式写出 `参考图组：当前 skill 的 assets/reference-pictures/`、`借鉴点：框架 / 结构 / 排版 / 思维链 / 配色`、`仅借鉴形式，不复制具体内容、数据、标签、结论`，以及 `布局原型`、`阅读方向`、`主色家族`、`区分点`，且不得出现 `禁止编造`、`禁止造假`、`结果复核`、`三轮复核`、`不得抄袭`、`可复现`、`可信输出` 等流程污染词；`## 硬约束` 只放硬约束与负面约束，若出现上述流程词，必须明确写成“不渲染为图内可见文字”。同批提示词在布局原型、阅读方向、主色家族、区分点中至少 2 项显式不同，且至少覆盖原理图、模型图、概念示意图三类；若提示词要求图内出现符号或公式，必须声明与论文符号说明、模型公式、`results/final_results.json` 和 `Qn/result.md` 保持一致，不得自行创造符号或改写公式。正文显示提示词路径时，每行只放 1 个相对路径，不得把多个 `手绘图/*.md` 挤在同一长行。后续提示词复核与生图模型都必须优先吸收当前 skill `assets/reference-pictures/` 的内置参考图组，不允许改读 skill 外部图片路径。
- 用户约定论文页数且正文不足时，只能深化“模型建立与求解”：补变量定义、约束来源、公式推导链、适用条件、边界讨论、求解细节、结果解释和上下文衔接；禁止为凑页新增“综合解释”“图表策略”“落地建议”“创新性总结”“迁移应用讨论”“质量控制复核”等与模型求解弱相关的大章节。
- 除参考文献、附录和代码外均视为论文正文；正文默认不少于 16 页，若用户明确要求更高正文页数，以用户要求为准且不得低于 16 页。
- 单问建模、公式推导和论文论述必须先压出 4 到 6 步主线骨架，每步写清输入、依据和输出；变量先定义，公式逐步推导，外部定理或标准结论必须说明调用目的。
- 深化论文时优先补变量定义、约束来源、推导链、适用条件、边界讨论、求解细节和结果回扣；禁止用套话、无关章节或重复图表冒充深度。
- 正文禁止实际字符 `•`、`☐` 和会生成圆点项目符号的 `itemize` 环境；需要列举时使用自然段、编号句、`enumerate` 或表格。
- 正文引用必须使用与参考文献条目真实关联的引用命令，并在引用处显示为右上角数字角标；优先复用亚太杯模板已有上标引文命令，缺失时定义兼容模板的 `\supercite{key}`（内部调用 `\cite{key}`），禁止手写 `[1]`、手工编号或生成与文后条目失联的角标。网上资源仍须保留访问日期；编译后抽查角标位置、编号与文后条目一一对应。
- 只为核心机理、目标函数、关键约束、鲁棒判据、敏感性指标等承担主链作用的少数重要公式编号；定义性补充、中间代换、重复指标和解释性公式使用无编号环境。多行但属于同一逻辑单元的公式整组只保留一个编号，编号必须唯一、连续并位于公式右侧，严禁为了缩减编号改写公式内容。
- 摘要中每个“针对问题一/二/.../X”只加粗该标签短语，标签后的标点和正文不得随标签进入同一粗体命令；每问再选择性加粗重要算法、核心模型和主要结论。“关键词”三个字及分号分隔的所有关键词必须分别加粗。正文只选择关键模型、决定性判据、核心数值结论和最终推荐中的短语加粗，原则上不加粗完整句，禁止连续多句、整段或逐段机械强调。编译后必须确认中文粗体真实可见；内置模板统一使用 `\paperstrong{}` 切换黑体，用户模板若无等价命令则局部定义同名命令，禁止依赖宋体伪粗体或全局替换正文主字体。
- 将适合正式 APMCM 中文赛论文的自然写作与论文主线设计直接融入 Step2-Step4，不额外触发、导入或依赖 `humanizer`、`paper-spine`，也不新增它们的配置、确认门或中间产物：先明确每问的贡献、权威数据或计算证据、结论边界和评委可能质疑点，再安排段落功能，使结果逐项验证模型承诺。删除重复定义、同义复述、空泛承接、模板化三段式、宣传性措辞、模糊归因和无依据的“显然、由此可知”；标题、摘要至模型评价的可见论述不使用“首先、其次、然后、接着”机械组织段落，重复套话必须改用具体证据推进。用具体变量、权威数据、计算结果或图表证据推进论证，保持正式、克制、自然的竞赛论文语体。不得为“人味”加入适用于博客的闲聊、幽默、刻意凌乱、感叹、虚构细节、情绪化判断或不必要的第一人称。
- 写作完成后执行“草稿—审计—定稿”闭环：检查每段是否服务贡献主线、结果是否验证模型承诺、结论是否超出证据、图表和表格后是否紧跟对应解释，并重点压缩解释堆叠与重复结论。只删真正冗余，保留变量定义、数据来源、推导桥梁、适用条件和边界讨论。论文若由脚本或模板生成，必须同步修改生成源与最终 `main.tex`，再重新生成或编译，防止后续覆盖。

## 快速流程

1. **Step0 项目初始化**：建立 `数据/`、`赛题/`、`文献/`、`数据预处理/`、`Q1...Qn/`、`灵敏度分析/`、`手绘图/`、`摘要/`、`论文/`、`results/`、`检查结果/`；初始化 `数据/data.md`、`数据/data.xlsx` 和 `手绘图/README.md`。
2. **Step1 引入与数据预处理**：先拆题，明确变量、目标、约束、评价指标和数据缺口；再按官网和权威平台优先策略搜索数据；清洗、审计和 EDA 结果必须可复现。
3. **Step2 单问建模**：每问比较候选方法，给出变量、目标函数、约束、求解策略和可解释性说明；数据不足时继续搜索权威数据。
4. **Step3 代码实现**：Python 复现模型、图表和结果；最终数值写入 `results/final_results.json`，各问代码和结果保留在对应 `Qn/`。
5. **Step4 论文写作与排版**：优先使用用户指定的 APMCM 中文赛项目模板，缺失时使用 skill 内置备用模板；正文前必须按锁定模式完成至少一张技术路线图或问题分析图并插入论文，同时完成角标引文、选择性公式编号、重点加粗和自然文风审计。

## 数据记录最低要求

`数据/data.md` 中每条数据至少包含：

- 数据名称
- 来源机构
- 可点击 URL
- 访问日期
- 下载或获取方式
- 字段说明
- 数据作用
- 适用问题
- 可信等级
- 清洗与变换记录

`数据/data.xlsx` 至少包含这些工作表：

- `数据清单`
- `原始数据索引`

## 模板使用

- 优先使用用户指定的 APMCM 中文赛项目模板；缺失时复制 `assets/templates/main.tex`。
- 用户指定的项目模板 `main.tex` 是亚太杯中文赛专用模板，参考用户指定的 APMCM 中文赛论文模板 DOCX。
- 模板必须保持 APMCM 中文赛风格：封面信息、摘要、正文、参考文献、附录。摘要必须严格限制在第一页内并尽量写满第一页，建议 800-1000 字；摘要页必须到关键词结束，关键词后的正文第一节必须另开新页，禁止“一、问题重述”和摘要同页。
- 生成或更新 `论文/main.tex` 后必须立即在 `论文/` 下运行 XeLaTeX 编译；若 `main.log` 出现硬错误，必须按最小改动修复并重新编译，直到 `main.pdf`、`main.aux` 存在且无硬错误，并写入 `检查结果/latex_compile_record.md`。
- 附录“支撑材料文件目录”只允许列数据预处理代码、灵敏度分析代码、Q1-Q4 代码，以及题目明确要求提交或输出的结果 `.xlsx/.xls/.csv`；结果文件必须有 `检查结果/题目要求结果清单.md` 的题目依据和允许文件名。附录“附录代码文件”只放完整 Q1-Q4 代码和完整灵敏度分析代码，禁止放总控脚本、数据预处理脚本、绘图脚本、检查脚本、配置脚本或结果文件，且代码必须无注释。
- 禁止 `\tableofcontents`、普通 `\maketitle` 和普通 `abstract` 环境。
- 参考文献必须支持书籍、期刊和网上资源，其中网上资源必须写访问日期。

## 交付门禁

最终交付前必须完成三轮全链路自查，并写入 `检查结果/三轮自查.md`：第一轮检查内容与数据链，第二轮检查论文与版式链，第三轮检查代码与复现链；自查必须覆盖正文符号、支撑材料目录、摘要页约束、普通柱状图必要性、顶刊一区中文三维图可行性评估和正文页数是否达标，其中摘要页约束必须写明一页内、尽量写满、`abstract:end` 和编译页码复核。另需写入 `检查结果/推理论证复核.md`，覆盖主线骨架、变量定义、公式推导链、假设来源、上下文衔接、边界讨论和结果回扣。

随后运行：

```powershell
python <DSH_HOME>\skills\yatai-cn\scripts\checks\run_all_checks.py --project <项目根目录>
```

检查报告必须落入 `检查结果/check_report.json` 和 `检查结果/check_report.md`。失败项必须先修正，不得用口头说明替代。
