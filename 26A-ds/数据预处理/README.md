# 数据预处理

本目录负责把赛题附件的 100 个计算图用例解析为可建模的结构化数据，并给出
探索性分析（EDA）结论。所有原始文件均为只读输入，处理过程不修改任何官方文件。

## 原始输入

- 赛题附件压缩包 `赛题/通用神经网络处理器下的多核调度问题  附件.zip` 内的
  `data/case_001.json` ～ `data/case_100.json`，每个文件是一张 Op-Tensor 二部图，
  顶层包含 `tensors`、`ops`、`edges` 三个数组。
- 固定评估配置 `data/config.txt`（L1 与 UB 容量、共享 DDR 带宽、场景 A/B 等待周期、
  问题三只读 Cache 容量与带宽）。
- 官方算法说明 `docs/核内调度算法.md`、`docs/多核并行模拟执行算法.md`，用于对齐
  评估口径。

## 处理规则

1. **操作级 DAG 收缩**：把张量中转边合并为操作间的直接依赖，`COPY_IN` 与
   `COPY_OUT` 作为中转节点被跳过，得到仅含核内操作的依赖关系。
2. **工作量折算**：操作权重取 `op.cycles`，按 `pipe` 字段分别累计 `PIPE_M` 与
   `PIPE_V` 的工作量；搬运操作的字节量按张量 `size` 累计。
3. **关键路径**：在操作级 DAG 上计算最长加权路径，作为并行度的下界。
4. **并行宽度**：定义为总工作量与关键路径之比，用于判断用例是否本质串行。
5. **规模统计**：按张量 `pos` 字段分组求 DDR/L1/UB 字节总量与单张量最大值。

## EDA 结论

- 100 个用例的核内操作规模从 552 到 35705，跨越中小图到超大规模图；
- 并行宽度中位数约 43，多数用例存在充足并行空间，但存在并行宽度接近 1 的
  本质串行用例，这类用例的加速比上限接近 1；
- 矩阵流水线工作量在多数用例中显著高于向量流水线，切图时必须以 PIPE_M 负载
  均衡为主要目标；
- 关键路径中位数约 6100 周期，远小于总工作量中位数约 51 万周期，说明任务级
  切分的主要风险不是关键路径，而是跨核同步等待与边界搬运的累积。

## 输出

| 文件 | 内容 |
|---|---|
| `data/case_profile.csv` | 100 个用例的结构画像，每行一个用例，列为节点数、边数、各流水线周期、关键路径、并行宽度、DDR/L1/UB 字节数等 |
| `数据预处理/audit.json` | 处理规则、缺失值/重复值/异常值处理说明、统计摘要与结论 |
| `data/source_map.md` | 逐条数据来源映射 |

## 复现命令

```powershell
python 数据预处理/build_dataset.py
```

脚本会自动定位赛题附件解压目录；若解压目录不在项目内，可通过环境变量
`HUAWEI_SUITE_DIR` 指定。
