# 问题二（场景 B）建模说明

## 目标

在存在核间同步机制的场景 B 下，建立适用于同核子图合并的切图与调度模型，
在严格满足 L1/UB 容量约束的前提下进一步缩短 Makespan 并减少额外数据搬运。

## 输入

- 与问题一相同的计算图与固定配置；
- 场景 B 规则：同一核心上的全部子图合并为一个 Task，同核子图之间的数据保留在
  L1/UB 中直接复用，不插入边界 COPY；只有跨核数据边才在源核插入 `COPY_OUT`、
  在目标核插入 `COPY_IN`，并支付 500 周期同步延迟。

## 核心假设

1. 同核子图之间的数据驻留不额外消耗带宽，但持续占用 L1/UB 空间，会压缩其他子图
   的可用容量；
2. 跨核同步延迟为固定周期数，与数据量无关；
3. 核内调度仍由官方确定性启发式完成，容量不足时自动插入缓存换出与换入；
4. 子图依赖图必须无环。

## 变量

| 符号 | 含义 |
|---|---|
| $G_k$ | 第 $k$ 个子图 |
| $c_k$ | 子图 $k$ 所属核心 |
| $\mathcal{T}_c$ | 核心 $c$ 上全部子图合并后的 Task |
| $B^{\mathrm{cross}}_c$ | 核心 $c$ 的跨核边界搬运字节 |
| $\tau$ | 跨核同步延迟，取 500 周期 |
| $D^{\mathrm{B}}_k$ | 场景 B 下子图 $k$ 的估算时长 |

## 模型与公式

**Task 构造。** 对每个核心 $c$，$\mathcal{T}_c=\bigcup_{k: c_k=c} G_k$。同核子图之间
的依赖不产生搬运，因此场景 B 的通信代价只来自跨核边：

$$B^{\mathrm{cross}}=\sum_{(u,v)\in E,\ c(u)\neq c(v)} s_{t(u,v)}$$

其中 $s_{t(u,v)}$ 是承载该依赖的张量字节数。

**容量压力。** 合并后 Task 的 L1/UB 驻留峰值决定是否发生换出换入。设核心 $c$ 上
驻留张量集合为 $\mathcal{R}_c$，容量约束为

$$\sum_{t\in\mathcal{R}_c} s_t \le \mathrm{Cap}(\mathrm{pos}(t)),\qquad \mathrm{pos}\in\{\mathrm{L1},\mathrm{UB}\}$$

容量不足时，官方核内调度器从不属于当前操作输入输出、且未来仍会使用的驻留张量中，
选择下一次使用最晚者换出；若 DDR 中没有有效副本，先插入 `COPY_OUT` 写回。

**时长估算。** 场景 B 的入向边界不再包含同核子图之间的搬运，因此

$$D^{\mathrm{B}}_k=\max\Bigl(M_k,\;V_k,\;\frac{B^{\mathrm{in,cross}}_k}{\mathrm{BW}},\;\frac{B^{\mathrm{out,cross}}_k}{\mathrm{BW}}\Bigr)$$

**分核决策。** 与问题一相同的 HEFT 式列表调度，但跨核等待常数改为 $\tau=500$，
且同核连续子图合并为同一 Task，不再逐子图支付换 Task 等待。

## 约束

1. 每个核内操作必须且只能属于一个子图；
2. 每个子图必须且只能被调度一次；
3. 同核子图顺序不得违反子图依赖；
4. 子图依赖图必须无环；
5. 合并 Task 的 L1/UB 驻留峰值不得超过对应容量。

## 方法

主方法与问题一保持一致，只替换代价口径：入向边界只统计跨核部分，跨核等待常数由
1000 降为 500。这样可以复用同一套无环性构造，同时让分核阶段按场景 B 的真实代价
重新均衡负载。

## 验证设计

1. 全部 100 个用例、1～5 核配置下调用问题二官方评估程序；
2. 与问题一在相同核数下逐用例对照，检查场景 B 的 Makespan 是否不劣于场景 A；
3. 检查额外搬运量相对问题一是否下降，确认同核数据驻留确实减少了 DDR 流量；
4. 对容量紧张的大规模用例，核对额外搬运量中换出换入所占比例。
