# 问题三（共享只读 L2）建模说明

## 目标

在场景 B 的基础上引入所有核心共享的只读 L2 Cache（容量 1 MB，带宽
250 bytes/cycle，与 DDR 带宽相互独立），研究其容量与带宽对多核切图与调度的影响，
建立相应模型、设计求解算法，并给出无 L2 与只读 Cache 两种配置的对比与加速比。

## 输入

- 与问题二相同的计算图与固定配置；
- 只读 L2 参数：容量 1048576 字节，命中带宽 250 bytes/cycle；
- 评估规则：`COPY_IN` 发射时按逻辑张量 id 查询只读 FIFO Cache，命中不改变 FIFO
  顺序并进入 Cache 读带宽池；未命中则访问 DDR，完成后写入 Cache，容量不足时按
  先进先出淘汰；单个张量大于 Cache 容量时不缓存。

## 核心假设

1. L2 为只读缓存，写入不经过 L2，因此只有 `COPY_IN` 会查询 L2；
2. Cache 读带宽与 DDR 带宽是两个独立的带宽池，互不占用；
3. 同一逻辑张量的重复读取按 FIFO 顺序命中，命中收益表现为带宽提升而不是
   流量减少；
4. 切分阶段可用「读入边界的有效带宽」近似刻画 L2 的影响。

## 变量

| 符号 | 含义 |
|---|---|
| $\mathrm{BW}_{\mathrm{ddr}}$ | DDR 带宽，60 字节/周期 |
| $\mathrm{BW}_{\mathrm{L2}}$ | L2 命中带宽，250 字节/周期 |
| $g(t)$ | 张量 $t$ 被读取的核心数（消费者所在子图的核数） |
| $B^{\mathrm{in}}_k$ | 子图 $k$ 的入向边界字节 |
| $h$ | Cache 命中率，命中字节与总访问字节之比 |

## 模型与公式

**L2 复用模型。** 对一份被 $g(t)$ 个核心读取的 DDR 张量，第一次访问未命中，
经 DDR 读入并写入 Cache；其后 $g(t)-1$ 次访问命中，由 L2 以更高带宽服务。
因此该张量的有效读入时间代价为

$$T(t)=\frac{s_t}{\mathrm{BW}_{\mathrm{ddr}}}+(g(t)-1)\cdot\frac{s_t}{\mathrm{BW}_{\mathrm{L2}}}$$

**有效带宽近似。** 在切分阶段，把入向边界搬运统一按 L2 带宽折算：

$$D^{\mathrm{C}}_k=\max\Bigl(M_k,\;V_k,\;\frac{B^{\mathrm{in}}_k}{\mathrm{BW}_{\mathrm{L2}}},\;\frac{B^{\mathrm{out}}_k}{\mathrm{BW}_{\mathrm{ddr}}}\Bigr)$$

并额外加入全局 DDR 下界 $B^{\mathrm{ddr}}_{\text{总}}/\mathrm{BW}_{\mathrm{ddr}}$，
因为所有核心的首次读取仍然共享同一条 DDR 带宽。

**建模含义。** 无 L2 时把共享输入的消费者摊到多个核心要按 DDR 带宽付费，因此
切分倾向于把共享输入的消费者聚到同一核心；引入 L2 后这笔边际代价下降到约四分之一，
负载均衡与 L2 复用不再互相冲突，分核阶段可以更自由地追求均衡。

**命中率。** 命中率定义为

$$h=\frac{\text{命中字节}}{\text{总访问字节}}=\frac{\sum_{t}\bigl(g(t)-1\bigr)s_t\cdot\mathbf{1}[\,s_t\le \mathrm{Cap}_{\mathrm{L2}}\,]}{\sum_t g(t)\,s_t}$$

## 约束

1. 与问题二相同的子图覆盖、调度唯一性、依赖无环与同核顺序约束；
2. 合并 Task 的 L1/UB 驻留峰值不得超过容量；
3. 单个张量大于 L2 容量时不缓存，该张量的全部访问均记未命中。

## 方法

给出两条候选路线并逐用例实测择优：

- **路线一（L2 感知切分）**：把入向边界按 250 bytes/cycle 计入子图时长，切点
  坐标下降在新代价函数下重新搜索；
- **路线二（DDR 口径切分）**：入向边界仍按 60 bytes/cycle 计入，直接沿用问题二
  的方案，用于隔离 L2 本身的贡献。

两条路线的方案分别送入问题三官方评估程序实测 Makespan，逐用例取更优者作为最终
方案；无 L2 基线取问题二在同一核数下的结果。

## 验证设计

1. 全部 100 个用例、1～5 核下调用问题三官方评估程序，记录 Makespan、额外搬运量
   与 Cache 命中率；
2. 与无 L2 基线配对求加速比，检查加速比是否随核数变化并给出解释；
3. 核对命中率与用例中共享输入的规模是否一致；
4. 比较两条候选路线的实测 Makespan，统计各自胜出的用例数。
